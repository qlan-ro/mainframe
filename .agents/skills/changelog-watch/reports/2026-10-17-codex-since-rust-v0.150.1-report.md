Knock-on effect on CODEX-FILE-04 (`src/rollout_reconstruct.rs::handle_custom_tool_call`), because it is fed by the same reader.
- Why it threatens the row: when `local_thread_store_compression` is on, Codex rewrites rollouts older than 7 days to `rollout-…-<id>.jsonl.zst`. The `.jsonl` file is gone and no plain sibling is left (`codex-rs/rollout/src/compression.rs`, `COMPRESSED_SUFFIX = ".zst"`, `MIN_ROLLOUT_AGE` = 7 days). #42039 removes the carve-out that used to keep shared/forked lineages uncompressed, so the feature now covers every cold file. Mainframe's scanner drops any name that doesn't end in `.jsonl`, and `resolve_rollout_path` logs "rollout file not found" and returns nothing. Nothing surfaces to the user: week-old external sessions vanish from the resume list, sub-agent child-thread reconstruction comes back empty, and cold-load PR scanning loses its command output. It is medium rather than high because, at rust-v0.154.0, `local_thread_store_compression` is still `Stage::UnderDevelopment`, `default_enabled: false` (checked in `codex-rs/features/src/lib.rs` at the tag). Only users who opt in hit it today. It becomes high in the release where that default flips. This backs up the 2026-08-27 high risk "Rollout migration tooling and background migration" (CODEX-FILE-01). `background_paginated_rollout_migration` is also still default-off at 0.154.0 (#43178 "Allow guarded legacy resume with background migration enabled" adds guards for it), so both on-disk format changes are opt-in for now.

## Adoption opportunities

- **External messages via `toolOutput` turn input** — "Add `ExternalMessage` to synchronous and asynchronous `run()` and `turn()` calls. External content can start a turn or join an active regular turn with tool-level authority; it does not grant user authorization." (python-v0.154.0, #44086). The SDK sends this through the app-server's `toolOutput` turn input (#41002, CLI ≥ 0.151.0), and history keeps it as function output. Mainframe currently delivers delegated-task results and other agent output as user text. This would let orchestration inject them with tool-level authority instead. It would land in `src/session_prompt.rs::prompt_params` / `src/orchestration_args.rs`, plus a `FunctionCallOutput` variant in `src/item_types.rs::ThreadItem`, which Mainframe lacks today (see "Outside the notes" below). Size: medium.
- **Answer structured async questions inline** — "Answer questions inline while Codex continues working, using suggested choices or custom text without losing your main draft." (rust-v0.154.0, #42891/#42894/#42897). The wire side already reaches Mainframe: `AgentMessageItem.delivery == async` and `questions: [{title, options}]` deserialize in `src/thread_item_variants.rs` / `src/presentation_fields.rs`. Today they are used only to suppress the final-answer phase, so the question shows as plain text with no choices. Rendering the options as answer chips that send through `turn/steer` (CODEX-RPC-09) is a UI affordance. This matters more now that GPT-6-Astra is the bundled default model (0.153.4) and is told to use async questions. Size: medium.

## Outside the notes

- v2 `ThreadItem` gained a `functionCallOutput` variant between rust-v0.150.1 and rust-v0.154.0. It came from #41002 "Support standalone tool outputs in `turn/start`", which is not in any changelog in this range (found by diffing `schema/typescript/v2/ThreadItem.ts` across the two tags). `src/item_types.rs::ThreadItem` has no matching variant, so such items are dropped (CODEX-ITEM-01's stated symptom). Mainframe never sends `toolOutput`, so its own threads should not contain them. A thread that a Python SDK `ExternalMessage` wrote to and that Mainframe later resumes would lose them. Low, and it goes away if the ExternalMessage opportunity above is taken. The ITEM-01 row also says "18 variants". Upstream v2 now has 19, including `plan` (which Mainframe handles through `item/plan/delta`) and `functionCallOutput`. Mainframe's own enum has `todoList`, which v2 no longer emits.
- Checklist gaps seen during this pass: no row cites `src/presentation_fields.rs` (`AgentMessage.delivery`/`questions`), and CODEX-EVT-04 doesn't cite `src/context_window.rs`, a hardcoded snapshot of 0.153.4's catalog windows used when `tokenUsage.modelContextWindow` is absent.
