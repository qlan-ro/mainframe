# changelog-watch: claude 2.1.312 → 2.1.314 (2026-10-30)

Entries seen: 119 · risks: 0 · opportunities: 1 · relevant, no action: 27 · dropped as irrelevant: 91

The upstream changelog has no 2.1.313 entry, so this pass covers only 2.1.314. No checklist row breaks. The installed CLI is still 2.1.310, so nothing here was run live. Two entries could have been risks, so I checked them against strings extracted from the 2.1.314 `darwin-arm64` binary (`npm pack @anthropic-ai/claude-code-darwin-arm64@2.1.314`; the binary was not executed):

- **Idle compaction** (the "added" and "changed" entries). An unprompted compaction between turns would emit `compact_boundary`/`status: compacting` while Mainframe thinks the chat is idle. The scheduler only arms when `MU()` is true: `CLAUDE_CODE_SESSION_KIND` is not `bg`/`daemon`/`daemon-worker`, and the session is either interactive (TUI) or a non-child session whose entrypoint is one of `claude-vscode`, `claude-desktop`, `claude-desktop-3p`, `local-agent`, `remote*`, `ssh-remote`, `claude-in-slack`, `claude-in-teams`, `claude-coworker*`. Mainframe spawns headless stream-json and sets no `CLAUDE_CODE_ENTRYPOINT` (grep over `packages/core-rs/crates` finds none), so idle compaction never runs in a Mainframe session.
- **Esc/Stop now tells Claude the command "may have run".** If this text were appended to the `[Request interrupted by user…]` marker, `user_event.rs::is_interrupt_marker` would stop matching and the marker would leak in as a CLI message. In the binary the new text is a separate correction (`… Correction to the text above: this call was stopped while running, not refused before it ran. It may have run in part or in full …`) appended to the interrupted call's tool_result content. The user-text marker is untouched.

## Adoption opportunities

- `permissions.blockWritesOutsideWorkingDirectories`. Write/Edit/NotebookEdit refuse paths outside the working directories in every permission mode, including `bypassPermissions`. It would fit worktree chats, where an agent should not write into the main checkout. It would land in session spawn as a per-chat "confine writes to the worktree" toggle. Mainframe passes no `--settings` today, and it is unverified whether `apply_flag_settings` accepts a `permissions.*` key, so check with the claude-protocol-debugger first. Size: medium.
