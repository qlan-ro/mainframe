# changelog-watch: claude 2.1.322 → 2.1.323 (2026-11-13)

Entries seen: 294 · risks: 9 (3 findings) · opportunities: 2 · relevant, no action: 49 · dropped as irrelevant: 234

One very large version. Three findings. The serious one: the CLI now assumes a 1M context window for any model ID it doesn't recognize. Every CLIProxy model Mainframe offers is such an ID, so proxy chats lose early autocompaction and can fail every turn once the real window fills. Second, `--permission-mode auto` now falls back to Manual when auto is unavailable, and Mainframe never reads the effective mode back. Third, several new startup notices may land on stderr in stream-json runs, where Mainframe shows unmatched stderr as a chat error. Most of the rest hardens Bash permission checks. That changes when `can_use_tool` fires, not its shape.

The installed CLI is 2.1.318, so none of this was checked live in this run.

## Compatibility risks

### high — Changed the context window assumed for a model ID that Claude Code doesn't recognize from 200K to 1M; use `/autocompact` to compact earlier, or `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` to keep 200K (2.1.323)

Folded in: "Changed sessions on other vendors' models with a smaller window: once full, they can fail every turn until `/clear`, so set `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` before they fill" (same version).

- Checklist row: `CLAUDE-ENV-01`, plus `CLAUDE-CTRL-02` for the gauge. Consumers: `src/cliproxy.rs::resolve_env` and `src/session_spawn.rs::build_spawn_command`, which build the proxy env. `src/events.rs::handle_control_response_event` reads `maxTokens` for the context gauge.
- Why it threatens the row: CLIProxy chats spawn `claude` with `--model gpt-5.6-sol`, Kimi models and similar IDs that the CLI doesn't recognize. `cliproxy.rs` notes that the proxy publishes no context window (`ProxyModel`, `context_window: None`). Until 2.1.322 the CLI assumed 200K for these, which is below their real windows (roughly 256K–400K), so autocompaction fired in time. From 2.1.323 it assumes 1M. Autocompaction then never fires before the provider's real limit. Upstream says such sessions "can fail every turn until `/clear`". Nothing errors until the window is full, and then the chat is stuck. The context gauge also shows a 1M denominator from `get_context_usage`. Mainframe sets none of `CLAUDE_CODE_DISABLE_1M_CONTEXT`, `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` or an `/autocompact` setting (grep over `packages/core-rs/crates` finds none).
- Fix direction (for the todo, not this run): add `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` to `CliProxyEnv` so it is applied only to `cliproxy/` chats. 200K sits below every current proxy model's window, so compaction comes early but safely. Native Anthropic chats must not get it, because they rely on the 1M window.
- Recommended regression test: extend `src/session_tests_spawn_part_1.rs::a_proxy_session_is_pointed_at_the_endpoint_and_stripped_of_the_real_api_key` to assert that the spawned command's env holds `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`. Extend `a_native_session_carries_no_endpoint_env` to assert that the variable is absent.
- Verify live: .claude/skills/claude-protocol-debugger/. On 2.1.323, start a proxy chat and send `get_context_usage`. Expect `maxTokens: 1000000` without the env var and `200000` with it.

### medium — Fixed `--permission-mode auto` or a settings `defaultMode: auto` starting in a mode that could allow more when auto mode was unavailable. It now starts in Manual mode, which asks first (2.1.323)

Folded in: "Fixed auto mode running behind a gateway at `ANTHROPIC_BASE_URL` on a model whose gateway name contains "haiku"; such a model, other than `claude-haiku-5-5`, is now refused, as Haiku 4.5 is" (same version). That is one more way auto becomes unavailable, and the result is the same Manual fallback.

- Checklist row: `CLAUDE-FLAG-01`. Consumers: `src/session_spawn.rs::build_args` (always passes `--permission-mode`), and `src/session_controls.rs`, which maps `ExecutionMode::Auto` to `auto`.
- Why it threatens the row: the row assumes `--permission-mode auto` gives an auto-mode session. When auto is unavailable for the account, model or gateway, the CLI now starts in Manual instead. The adapter never reads the effective mode back: no code under `mainframe-adapter-claude/src` reads `permissionMode` from `init`. So the composer keeps showing Auto while every tool call raises a gate. The session works but visibly misbehaves. The new fallback is safer than the old one.
- Recommended regression test: add `#[test] init_with_default_permission_mode_after_auto_was_requested_reports_the_fallback` in `src/events_tests_notifications.rs`. Pin `{"type":"system","subtype":"init","session_id":"s1","permissionMode":"default"}` on a session spawned with `ExecutionMode::Auto`, and assert that the sink receives the effective mode (or a mode-mismatch notice), not just that the init parsed. This needs a small handler change in `src/events.rs::handle_system_event`.
- Verify live: .claude/skills/claude-protocol-debugger/. On 2.1.323, find a setup where auto is unavailable (for example a `cliproxy/` model, or an account without auto). Spawn with `--permission-mode auto`, then confirm what `init.permissionMode` reports and that a `can_use_tool` request arrives for an edit.

### low — new startup notices may surface as chat errors (2.1.323)

Entries:
- "Deprecated a plugin's `agent` setting: it still applies, and now warns at startup, in `claude plugin list` and in `claude plugin validate`"
- "Fixed the misleading "not cached" error for a plugin only a repository's settings enable: it now says it isn't installed, gives the install command, and shows in text and stream-json `-p` runs"
- "Added a start-up warning for Bash allow rules with a `*` in a variable's value, such as `Bash(PORT=* npm run dev)`"
- "Added a warning when a plugin's language server can't start, naming the server and what to check"
- "Added a one-time startup notice naming `CLAUDE_CODE_PERFORCE_MODE` when Perforce settings are found and the mode is off"

- Checklist row: `CLAUDE-IO-01`. Consumer: `src/events.rs::handle_stderr`.
- Why it threatens the row: `handle_stderr` drops only the six noise prefixes and the trust advisory. Every other stderr chunk goes to `sink.on_error`. The plugin entry says outright that the message now appears in stream-json `-p` runs. If any of these notices goes to stderr and not to a `system` event, users with a matching setup get an error in the chat on every spawn. The session keeps working. The channel is unconfirmed: these may be TUI-only notices, or `system` events that the adapter skips at debug.
- Recommended regression test: once the live check captures the exact wording, extend `src/events_tests_stderr.rs::stderr_filters_informational_and_empty` with each confirmed notice and assert that `on_error` is not called. Do not add a filter before the wording is known.
- Verify live: .claude/skills/claude-protocol-debugger/. On 2.1.323, spawn the stream-json argv in a project where a plugin uses the `agent` setting and where `.claude/settings.json` enables an uninstalled plugin. Record which notices reach stderr and which arrive as events.

## Adoption opportunities

- **`init.plugin_errors`**: "Fixed load errors of plugins enabled by managed settings going only to the debug log in SDK and Desktop sessions: `init.plugin_errors` now lists them" (2.1.323). The `init` event now carries plugin load errors. `src/events.rs::handle_system_event` reads only `session_id` from `init` (`CLAUDE-EVT-01`). It would land there and be shown as a session notice. Size: small to log, medium to show in the UI.
- **`/usage` bars for setup tokens**: "Fixed `/usage` hiding limit bars for setup tokens and `CLAUDE_CODE_OAUTH_TOKEN`: it keeps the session and weekly bars and says why the rest are missing" (2.1.323). Users on those tokens now get session and weekly bars, but the quota pull will still show Unknown. `src/quota_parse.rs::parse_claude_usage` fails the whole provider to Unknown on any line it can't classify, and the new "why the rest are missing" line is one (`CLAUDE-PROBE-03`). Capture the wording live, then skip that line explicitly. Size: small.
