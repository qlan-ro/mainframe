Main points: no compatibility risk. Nothing here changes a shape Mainframe reads. Most of the volume is TUI work (side-chat tabs, the full-screen transcript, the opt-in Cloud backend), Guardian reviewers, gateway authentication and Bazel builds. The two upstream additions worth a look are app-server methods for model providers and a moderation field on agent messages. Both are opportunities.

I compared the app-server protocol at both tags instead of trusting the prose. A definition-level diff of `codex-rs/app-server-protocol/schema/json/codex_app_server_protocol.v2.schemas.json` shows no removed definitions and no change to `ServerNotification`, `ServerRequest.json`, `ThreadStartParams`, `ThreadStartResponse`, `TurnStartParams`, `TurnError`, the token-usage or rate-limit types. `ClientRequest` gains three methods: `modelProvider/list`, `modelProvider/config/write` and `account/securitySetup/read`. The changed definitions are all additive optional fields: `GetAccountResponse.userId`, `ItemCompletedNotification.contentTokenCount`, `ModelListParams.modelProvider`, `ThreadItem` agentMessage `moderation`, `ThreadItemsListParams.deferOutput`, `ThreadListParams.currentAccountOnly`, `QueuedSubmission.responsesapiClientMetadata`, `McpResourceReadParams._meta`, `Config.client_search_provider`, an audio `file_id` arm in `FunctionCallOutputContentItem`, and a new `CodexErrorInfo` string `inferenceHookDenied`. The Codex crate has no `deny_unknown_fields`, so additive fields deserialize. `models.json` is byte-identical at both tags. The state DB is still `state_5.sqlite` (`codex-rs/state/src/sqlite.rs::STATE_DB_FILENAME`), and `codex-rs/state/migrations` has the same files (last: `0062_threads_attached_parent.sql`). The installed CLI is still 0.163.0, so nothing was run live.

## Adoption opportunities

- **Model providers and custom gateways over the app-server** (rust-v0.168.0: "The app-server reference covers listing model providers, creating custom gateways, and updating gateway, Bedrock, and GCP settings." #58845, #58876; rust-v0.169.0: "Add or edit custom model providers from the terminal…" #59779, #60009, #60186, #60486, #60662). New `modelProvider/list` returns `ModelProviderSummary {id, name, baseUrl, canEdit, settings}`, `modelProvider/config/write` edits one, and `model/list` takes an optional `modelProvider` to list another provider's models without changing the default. Gateway OAuth gains a device-code flow. Mainframe calls `model/list` with no params (`src/adapter.rs`) and shows only the default provider's catalog. It would land in the model probe in `src/adapter.rs` and the Codex settings pane. Size: medium.
- **Moderated answers** (#59842 Carry targeted moderation decisions on final-answer messages; #60172 Preserve display instructions in answer moderation). `agentMessage` items can now carry `moderation {moderated, display {action, blockType, …}}`, a presentation instruction for clients replaying history. Mainframe ignores the field and renders the text as usual. It would land in `src/thread_item_variants.rs` and `src/thread_item_render.rs`. Size: small.

## Relevant, no action

**Curated bullets**

- "`codex exec` keeps project configuration and MCP servers disabled in untrusted directories, even with `--sandbox workspace-write`. Use `--trust` with `codex exec` or `codex review` to explicitly save project trust." (#60041, rust-v0.169.0) — `CODEX-FLAG-04`: the title one-shot runs in an empty temp dir with `--ignore-user-config` and `-s read-only`, so there is no project config or MCP to disable. It never passes `--trust`, which upstream refuses together with `--ignore-user-config`. The new "project configuration disabled" warning goes to stderr; the title is read from stdout.
- "Interrupted turns now close cleanly, and delayed aborts or file approval cancellations no longer interrupt a later turn." (#59910, #60700, rust-v0.169.0) — `CODEX-RPC-03`/`CODEX-RPC-04`: #60700 is in the `thread/read` history builder. An aborted turn is now closed instead of staying current, and a late abort with an unknown turn id no longer marks another turn. That helps history and `fork_pin.rs::last_completed_turn_id`, which already skips `inProgress`. #59910 scopes a file-change approval cancellation to its own turn. `turn/interrupt` params are unchanged. Repeating it after the turn ends returns "no active turn to interrupt", which upstream already did.
- "Documented how app-server clients can list models or authorize a gateway for a configured provider without changing the default provider." (#59776, #59819, rust-v0.169.0) — `CODEX-RPC-05`: `modelProvider` is an optional `model/list` param. Mainframe sends none, so it keeps the default provider's list.
- "Updated bundled SQLite to 3.54 to pick up write-ahead log fixes." (#60432, rust-v0.169.0) — `CODEX-FILE-02`: same file name and migrations. Mainframe's read-only `SELECT` on `threads` is unaffected by the writer's SQLite version.
- "Local TUI history and resume pickers filter newly created threads by the signed-in ChatGPT account." (#58918, rust-v0.168.0) — `CODEX-FILE-01`: TUI pickers only. Mainframe scans rollout files directly and never calls `thread/list`, whose new `currentAccountOnly` param defaults to false.
- "Open and resumed chats use their saved model provider after you change the default for new chats." (#59503, rust-v0.168.0) — `CODEX-RPC-08`: Mainframe resumes with an explicit model and never changes the default provider.
- "Steering messages reach running turns when sent during the final transcript save or after switching back to a long-running chat." (#58877, #58998, rust-v0.168.0) — `CODEX-RPC-09`: an upstream fix that helps `turn/steer`. Params unchanged.
- "Enable `features.image_generation_animation` to generate or edit animated GIFs with optional frame count and timing controls." (#59073, rust-v0.168.0) — `CODEX-ITEM-01`: opt-in. The `imageGeneration` item shape is unchanged, and `image_generation_render.rs::media_type_from_extension` already maps `.gif` to `image/gif`. Only an inline `result` with no `savedPath` falls back to `.png`; browsers sniff the bytes for `<img>`.
- "Codex warns when `features.multi_agent` is explicitly configured and points to `agents.enabled` for disabling subagent tools." (#59479, rust-v0.168.0) — `CODEX-ITEM-03`: the flag stays on by default, so collab items are unchanged. The warning fires only for an explicit user or project setting; Mainframe sets none.
