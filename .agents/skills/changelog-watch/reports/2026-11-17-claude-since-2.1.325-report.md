# changelog-watch: claude 2.1.325 → 2.1.326 (2026-11-17)

Entries seen: 367 · risks: 1 · opportunities: 0 · relevant, no action: 39 · dropped as irrelevant: 327

The delta is one version, but a large one. No wire shape that Mainframe parses changes. Most of the relevant entries tighten permission checks (Bash, `cp`/`mv`, sign-in files, bypass mode, auto-mode wildcard rules). That makes `can_use_tool` fire more often but does not change its shape. The one risk is low: a disabled slash command now gets new wording, and Mainframe's history loader matches only the old wording.

Checked against the 2.1.326 darwin-arm64 binary (npm `@anthropic-ai/claude-code-darwin-arm64@2.1.326`, strings only, not run). The installed CLI is still 2.1.318.

- The new `--allowedTools` startup warning checks for broken parentheses: "Check for a missing ")", a space before "(", or text after ")"". Mainframe's `--allowedTools mcp__mainframe` has none, so it does not trigger the warning.
- The headless trust refusal on stderr still contains both "has not been trusted" and "hasTrustDialogAccepted", so `CLAUDE-IO-01`'s two-string match still holds.
- The worktree plugin-skip notice (`[skill-as-plugin] Project plugins in .claude/skills will not load: this process has entered a worktree and the Bash sandbox is or was on…`) applies only to a process that entered a worktree with the sandbox on.

Still open from earlier runs: the 2.1.323 high risk is not fixed on `origin/main`. CLIProxy chats assume a 1M window, and `git grep` finds no `CLAUDE_CODE_DISABLE_1M_CONTEXT` or `CLAUDE_CODE_MAX_CONTEXT_TOKENS` in `packages/core-rs`. Nothing in 2.1.326 changes that.

Checklist drift, unrelated to this delta: `CLAUDE-EVT-06` and the "Not consumed" list both say Mainframe never passes `--include-partial-messages`. But `src/session_spawn.rs:177` passes it, gated by the version probe in `src/partial_stream.rs`. Those two rows need updating in a separate change.

## Compatibility risks

### low — Improved commands that are off for your provider, sign-in or an environment variable such as `DISABLE_TELEMETRY` to say why instead of "Unknown command" (2.1.326)

- Checklist row: `CLAUDE-FILE-04` (history reconstruction), with `CLAUDE-IO-02` for the slash-command path. Consumer: `src/history_converters.rs::{synthesize_unknown_command_from_user_entry, match_unknown_command}`, called from `src/history.rs`.
- Why it threatens the row: on history load, Mainframe turns a user entry whose string content starts with `Unknown command:` or `Unknown skill:` into two messages: the `/name` the user typed and a System error. A command that is off for a reason now gets a new message (the binary has a new `off_for_setup` path). The policy-disabled case already used "`/x` isn't available in this session." in 2.1.318, and nothing matches that wording either. When the match fails, the entry falls through to `convert_history_entry`. After a reload, the CLI's explanation can then show as a user bubble, or not at all, instead of as an error under `/x`. The live path is not affected, because `user_event.rs` shows any non-meta CLI text as a cli message. Mainframe hits this when a user runs a command that is off for that chat, for example under `DISABLE_TELEMETRY` or on a CLIProxy gateway. The full new wording is built at runtime and could not be read from strings alone.
- Recommended regression test: add `#[test] synthesizes_a_system_error_for_a_command_that_is_off_in_this_session` in a new `src/history_converters_tests.rs`. No unknown-command synthesis test exists today. Pin a user entry `{"type":"user","uuid":"u1","message":{"role":"user","content":"/usage isn't available in this session."}}`. Assert that the result holds a User message with text `/usage` and a System message carrying the explanation, not just `Some(_)`. Also add an `Unknown command: /typo` case so the existing behaviour is pinned.
- Verify live: `.claude/skills/claude-protocol-debugger/`. Run a command that is off (for example with `DISABLE_TELEMETRY=1`) in a stream-json session. Then record the exact text and the JSONL entry shape: string content or a block array, and `isMeta`.
