# changelog-watch: claude 2.1.326 → 2.1.327 (2026-11-18)

Entries seen: 173 · risks: 0 · opportunities: 1 · relevant, no action: 33 · dropped as irrelevant: 139

One version. No wire shape that Mainframe parses changes. The relevant entries fall into three groups: resume and transcript fixes that help Mainframe after its SIGINT fallback, more permission prompts with the same `can_use_tool` shape, and Artifact approval and tool tweaks that stay away from the publish wording and the `mcp serve` list and read actions.

Checked against the 2.1.327 darwin-arm64 binary (npm `@anthropic-ai/claude-code-darwin-arm64@2.1.327`, strings only, not run). The installed CLI is still 2.1.318.

- The headless trust refusal still contains both "has not been trusted" and "hasTrustDialogAccepted", so `CLAUDE-IO-01`'s two-string match still holds.
- The new resume notice is built as `{...Rt("Earlier messages couldn't be loaded because part of this session's file is missing or damaged. Claude won't see them, so repeat anything it still needs.","warning"), persist: false}`. It is a non-persisted warning message, so it never reaches the JSONL. Whether it reaches stream-json, and with what `system` subtype, needs a live check (see the opportunity below).
- `CLAUDE_CODE_DISABLE_SHELL_HEAD_START` is present, matching the changelog.

Still open from earlier runs: the 2.1.323 high risk (CLIProxy chats assume a 1M window) and the 2.1.326 low risk (disabled-command wording, todo #433). Nothing in 2.1.327 touches either.

## Compatibility risks

None.

## Adoption opportunities

- "Added a line when a resumed session's earlier messages can't be loaded" (2.1.327) — the CLI now says when part of a resumed transcript is missing or damaged. If it reaches stream-json as a `system` event, `src/events.rs::handle_system_event` drops it today as an unknown subtype (`CLAUDE-EVT-01`). It would land there as a System notice in the transcript after a resume, which matters most after Mainframe's SIGINT fallback kills a process mid-write. Confirm the event's shape first with `.claude/skills/claude-protocol-debugger/` by resuming a session whose JSONL has a truncated middle line. Size: small.

- "Fixed cases where a session resumed after an empty reply or a killed command lost an answer, or brought back a rewound prompt, after another crash or a move to the background" — `CLAUDE-FILE-01`: fixes transcript writes. Path and format are unchanged.

- "Fixed Claude Code refusing to start when `https_proxy` or `HTTPS_PROXY` is a bare `host:port` and neither its input nor its output is a terminal (the desktop app, an SDK, cron)" — `CLAUDE-FLAG-01`: Mainframe spawns without a TTY, so users with such a proxy now get sessions instead of a startup failure. Argv is unchanged.
- "Fixed `claude -p` hanging before its first request when the fetch of a model's settings stalled, such as at a proxy; it now goes on without them after 10 seconds" — `CLAUDE-FLAG-02`: the quota pull and title generation can no longer hang there. Output is unchanged.
- "Changed non-interactive (`-p`) mode to run fewer git commands before the first request" — `CLAUDE-FLAG-02`: the auxiliary spawns start faster. Output is unchanged.

- "Fixed artifact publishes failing with "the source file changed between approval and publish" when a synced or remote-backed folder had only changed the file's timestamp" — `CLAUDE-PROBE-04`: fewer failed publishes. The success wording is unchanged.
