# changelog-watch: claude 2.1.328 → 2.1.329 (2026-11-20)

Entries seen: 130 · risks: 1 · opportunities: 0 · relevant, no action: 16 · dropped as irrelevant: 113

One version, and no wire shape that Mainframe parses changes. The one risk affects CLIProxy chats only: 2.1.329 removes the automatic retry, added in 2.1.326, at the output-token limit named in a `max_tokens` error. A proxy model that accepts fewer output tokens than the CLI asks for now fails the turn instead of retrying. Most of the volume is Code Mode, the self-hosted runner, `[VSCode]` and terminal fixes.

I compared the strings in the 2.1.328 and 2.1.329 darwin-arm64 builds (npm `@anthropic-ai/claude-code-darwin-arm64`) without running either one. The installed CLI is still 2.1.318.

- The headless `/usage` formatter (`Current session: N% used · resets …` lines, then "What's contributing to your usage?") is byte-identical in both builds. The 2.1.329 usage-credits wording fix changes only the TUI dialog's subtitle (`"You're out of usage credits · /usage-credits to buy more"`), so `parse_claude_usage` never sees it.
- The headless trust refusal still contains "has not been trusted" and "hasTrustDialogAccepted" (`CLAUDE-IO-01`). These strings appear the same number of times in both builds: every `CLAUDE-FLAG-01` argv flag, `can_use_tool`, `control_cancel_request`, `get_settings`, `rate_limit_event`, `compact_boundary`, and the `CLAUDE-RPC-01` keys (`files_read`, `file_list`, `saved_dir`, `saved_to`). No new `subtype:"…"` literal appears in 2.1.329.
- **Correction to earlier reports (`CLAUDE-PROBE-04`):** the fourth publish wording, "An earlier attempt of this call already created the Artifact at <url>", exists in 2.1.318 but not in the 2.1.328 or 2.1.329 bundle. The 2026-11-19 report said all four were present, and it was wrong. A retried create now reads "Created a new Artifact at <url> (version N) from … in an earlier attempt of this call. This attempt created nothing new". That still starts with the first prefix, so `published_artifacts` still detects the publish. The change predates this range. The row text and the `reads_every_publish_wording` fixture should be updated to the new sentence the next time someone edits the row.

Still open from earlier runs: the 2.1.323 high risk (CLIProxy chats assume a 1M window), the 2.1.326 low risk (disabled-command wording, todo #433) and the 2.1.328 low risk (managed-plugin exit delay against the 30 s one-shot timeouts). Nothing in 2.1.329 touches them.

## Compatibility risks

### medium — Removed 2.1.326's automatic retry at the limit named in a `max_tokens` error; behind a gateway whose model takes fewer output tokens, set `CLAUDE_CODE_MAX_OUTPUT_TOKENS` to that limit (2.1.329)

- Checklist row: `CLAUDE-ENV-01`. Consumers: `src/cliproxy.rs::resolve_env` and `src/session_spawn.rs::build_spawn_command`. They set `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN` and the Haiku model names for `cliproxy/` chats, but never `CLAUDE_CODE_MAX_OUTPUT_TOKENS`.
- Why it threatens the row: a CLIProxy chat is exactly the gateway this entry describes, and the CLI doesn't recognise its models. The 2026-11-18 report noted that 2.1.326 continues a reply cut at 32,000 output tokens with a limit of 128,000 on unrecognised models. Until now, when the proxied model refused that budget, the 2.1.326 retry recovered at the limit the error named. In 2.1.329 the turn ends with the API error instead. That holds for any request whose `max_tokens` is above the proxied model's ceiling. Medium: the failure is visible (an error result), the session keeps working, and it needs a long reply or a low-ceiling proxy model. Native Anthropic chats are unaffected.
- Recommended regression test: if Mainframe starts setting the variable for proxy chats (from a per-model limit the CLIProxy catalog provides, or a conservative default), extend `src/session_tests_spawn_part_1.rs::a_proxy_session_is_pointed_at_the_endpoint_and_stripped_of_the_real_api_key` to assert the child env carries `CLAUDE_CODE_MAX_OUTPUT_TOKENS=<limit>`. Also extend `a_native_session_carries_no_endpoint_env` to assert a native chat does not.
- Verify live: `.claude/skills/claude-protocol-debugger/`. Run a 2.1.329 CLIProxy chat on a model whose output ceiling is below 32,000 (or ask for a reply over 32,000 tokens on one below 128,000), and check whether the `result` is an error naming the limit, where 2.1.328 retried.

## Relevant, no action

- "Added a warning in the conversation, in Claude Desktop and other non-interactive hosts, when hooks in managed settings fail to load" — `CLAUDE-EVT-01`: 2.1.329 adds no new system subtype literal, so the warning travels on an existing message path. In the worst case it arrives as an unhandled subtype, which is logged at debug. It only appears on machines with managed hooks.
- "Fixed `~/.claude.json` sometimes being reset to defaults when a network stall or file lock made it unreadable and cleared during a save" — `CLAUDE-FILE-06`: an upstream fix that keeps `oauthAccount` and `projects[path].hasTrustDialogAccepted` from being wiped. Fewer `unknown` identity reads and lost trust grants. The keys are unchanged.
- "Fixed `/usage` saying usage credits are off when they had run out or reached the monthly limit, and `/model` not telling Pro and Max users when that limit blocks a model that runs on usage credits" — `CLAUDE-PROBE-03`: TUI subtitle only. The headless `-p /usage` formatter is byte-identical between the builds (see above).
- "Fixed background MCP tasks that stalled after a slow reconnect: Claude Code now reconnects most HTTP MCP servers by itself when one is left on an older protocol version" — `CLAUDE-FLAG-04`: the `mainframe` server is HTTP. Reconnection is CLI-side, and the injected `--mcp-config` is unchanged.
- "Fixed a background agent running on when it was stopped while it was being resumed" — `CLAUDE-CTRL-03`: a fix behind `stop_task`, the second step of Mainframe's interrupt escalation. Same request, more reliable effect.
- "Fixed Claude not being told that a connected MCP server's tools could not be loaded, and taking it for a server with no tools, in sessions with tool search" — `CLAUDE-FLAG-04`: if the `mainframe` tools fail to load, the model is now told so. No wire change.
- "Fixed auto mode asking for manual approval to `rm` a symlink that points outside the working directory or at itself" — `CLAUDE-CTRL-01`: fewer `can_use_tool` requests in auto mode. The request shape is unchanged.
- "Fixed a removed plugin's MCP server staying connected in headless sessions after `reload_plugins` or when the account's plugin list drops it" — `CLAUDE-CTRL-03`: Mainframe never sends `reload_plugins`.
- "Fixed a new skills, commands or agents folder being missed when `--add-dir` names the working directory or Claude Code starts in the home folder" — `CLAUDE-FILE-05`: Mainframe never passes `--add-dir`, and its skills panel uses its own scan.
- "Fixed sessions started from a pre-warmed process ignoring the `autoCompactWindow` setting in the project's `.claude/settings.json`" — `CLAUDE-FLAG-01`: Mainframe spawns each session cold and never uses a pre-warmed process.
- "Fixed headless rewind and fork going ahead while a message sent right after a model change still waited on it" — `CLAUDE-FILE-09`: Mainframe forks from a transcript snapshot with `--resume … --fork-session` at spawn, never by a live rewind or fork in a running session.
- "Fixed resumed sessions showing \"Rejected\" or \"Declined\" for edits, questions and plans that were cut off when the session ended" — `CLAUDE-FILE-04`: this is the CLI's own resume view. Mainframe rebuilds history from the JSONL tool_use and tool_result pairs, and the entry names no transcript change.
- "Improved the automatic clean-up of old sessions on computers with managed settings" — `CLAUDE-FILE-02`: transcripts may be deleted sooner on managed machines. The presence probe and degraded-chat recovery already handle a missing transcript.
- "Improved memory use of idle Claude Desktop and SDK sessions after a long turn, and after `--resume` or `--continue` of a session that holds screenshots or large tool results" — `CLAUDE-FLAG-01`: performance only. Argv and the transcript format are unchanged.
- "Changed auto mode to run `git status` less often so most requests wait less in large repositories; a git command that discards changes may be blocked until the working tree is checked" — `CLAUDE-CTRL-01`: auto-mode classifier internals. A block arrives as the usual denial.
- "Changed Code Mode to also start when telemetry, nonessential traffic or feature flags are turned off; an administrator can keep it off in managed settings" — `CLAUDE-EVT-02`: Code Mode is still listed as "(experimental)" in 2.1.329 and is a user opt-in that Mainframe never turns on. The 2.1.322 note still applies: if a user enables it, check the tool_use stream shape before relying on `TodoWrite`/`Bash`/`Skill` detection.
