# changelog-watch: claude 2.1.329 → 2.1.330 (2026-11-21)

Entries seen: 142 · risks: 0 · opportunities: 1 · relevant, no action: 19 · dropped as irrelevant: 122

One version, and nothing in it changes a stream-json field, control subtype, flag, env name or transcript path that Mainframe reads. One entry closes an open risk: 2.1.330 reverts 2.1.329's removal of the automatic retry at the output-token limit named in a `max_tokens` error. That was the 2.1.329 medium risk for CLIProxy chats, and once users are on 2.1.330 it no longer applies. Most of the volume is `[VSCode]` (28), self-hosted runner and Code Mode entries.

I compared the strings in the 2.1.329 and 2.1.330 darwin-arm64 builds (npm `@anthropic-ai/claude-code-darwin-arm64`) without running either one, and then read the 2.1.330 bundle for context on the items below. The installed CLI is still 2.1.318.

- New `initialize` keys `offersBypassSwitchBack` and `keepsBypassHeld` let the CLI start a `--permission-mode bypassPermissions` launch in `auto` instead. Mainframe always spawns with an explicit `--permission-mode`, so I checked this. The schema text says the switch happens "only then", meaning when the consumer sets `offersBypassSwitchBack`. It is "honored only on the session's first initialize … in the VS Code extension", and "ABSENCE fails closed: the session keeps the mode it was launched with". Mainframe's only `initialize` (`src/probe_models.rs`) declares neither key. `CLAUDE-FLAG-01` holds.
- easel, the new built-in chart mod, registers its tool as `mcp__easel__chart`. Its `isAvailable` requires a GrowthBook flag (`isOnByDefault: false`), macOS or Linux, and an org that is not HIPAA or ZDR. Nothing in it is limited to the terminal, so Mainframe chats on an eligible account may start seeing `mcp__easel__chart` tool calls. Not live-checked.

Still open from earlier runs: the 2.1.323 high risk (CLIProxy chats assume a 1M window), the 2.1.326 low risk (disabled-command wording, todo #433) and the 2.1.328 low risk (managed-plugin exit delay against the 30 s one-shot timeouts). Nothing in 2.1.330 touches them. The 2.1.329 medium risk (`max_tokens` retry removed) is resolved upstream by the revert below. If a todo was filed for it, close it, or narrow it to CLIs pinned at exactly 2.1.329.

## Adoption opportunities

- easel's `mcp__easel__chart` tool (2.1.330: "Added easel, a built-in mod that draws charts when asked and under MCP metrics results, on Pro, Max and, where available, Team and Enterprise on macOS and Linux"). In the terminal the mod draws the chart. In Mainframe the call would render as a generic MCP tool card with a raw input. The tool could be rendered as a chart in the tool card, or listed in `src/adapter/contract.rs::get_tool_categories` so it at least renders compactly. First capture a live `mcp__easel__chart` tool_use and tool_result on a gated account with `.claude/skills/claude-protocol-debugger/` to learn the input and result shapes. Size: medium (a new tool-card renderer); small if it only gets a category.

## Relevant, no action

- "Reverted 2.1.329's removal of the automatic retry when `max_tokens` exceeds a model's or gateway's limit" — `CLAUDE-ENV-01`: restores the 2.1.326 behaviour that CLIProxy chats relied on. It resolves the 2.1.329 medium risk instead of adding one.
- "Changed unrecognized model names containing \"sonnet\" or \"haiku\" to use the shorter system prompt, like other unrecognized names; `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0` gives every model the full one" — `CLAUDE-ENV-01`: CLIProxy models are non-Claude ids (`gpt-5.6-sol`, and the proxy rejects `claude-haiku-*`), so they were already unrecognized and already got the shorter prompt. Native chats pass recognized ids.
- "Fixed Claude Code freezing for up to several minutes right after compacting a very long conversation" — `CLAUDE-EVT-01`: a performance fix. `compact_boundary` and `status: compacting` are unchanged.
- "Fixed `--continue` and `--resume` opening an empty session or failing when the last saved message had a missing or invalid timestamp" — `CLAUDE-FLAG-01`: a fix behind the `--resume` that Mainframe passes, including fork snapshots (`CLAUDE-FILE-09`), which copy transcript lines verbatim. Fewer failed resumes, and the argv is unchanged.
- "Fixed turns failing with \"JSON schema is invalid\", and session files growing by many megabytes, when many MCP tools have an input schema that the API refuses" — `CLAUDE-FLAG-04`: applies only when the API refuses a tool schema. The `mainframe` server's tools and the injected `--mcp-config` are unchanged.
- "Fixed an MCP server that subagents declare being shut down when one of them finished, while other subagents or the session were still using it" — `CLAUDE-FLAG-04`: the `mainframe` server is declared at session level through `--mcp-config`, not by a subagent.
- "Fixed text and images added when approving a permission prompt being dropped when the approved command or tool then failed" — `CLAUDE-CTRL-04`: Mainframe's allow answer carries `updatedInput` and `updatedPermissions` but no `message` (`src/session_prompt.rs` sets `message` only on a deny), so nothing it sends was being dropped.
- "Fixed a stopped background subagent sometimes not staying stopped" — `CLAUDE-CTRL-03`: a fix behind `stop_task`, the second step of Mainframe's interrupt escalation. The request is the same and the effect is more reliable.
- "Fixed Claude still waiting for a background agent that was stopped just as it finished, in sessions run by an app or the SDK" — `CLAUDE-CTRL-03`: the same `stop_task` path, and this one applies to hosts like Mainframe. `task_notification` keeps its shape (`CLAUDE-EVT-01`).
- "Fixed background sessions sometimes waking in their previous permission mode after approving a plan" — `CLAUDE-CTRL-03`: concerns the CLI's own background sessions. Mainframe's `set_permission_mode` and `--permission-mode` are unchanged.
- "Fixed environment variables written by a SessionStart hook being lost with `claude -p --continue`" — `CLAUDE-FLAG-02`: Mainframe's one-shot `-p` spawns never pass `--continue`.
- "Fixed `claude -p` exiting 0 with no message when its output went to a file on a full disk: it now prints an error and exits 1, though a full NFS export may go unnoticed" — `CLAUDE-FLAG-02`: Mainframe reads one-shot stdout from a pipe, not a file. `src/quota_pull.rs` and `src/title_generator.rs` already treat a non-zero exit as a failure.
- "Fixed the system prompt keeping the earlier model's instructions when the model was changed after `/context` but before the first message" — `CLAUDE-CTRL-03`: if Mainframe sends `get_context_usage` and then `set_model` before the first turn, the new model now gets its own instructions. The request shapes are unchanged.
- "Fixed task dependencies and metadata being lost when several task updates ran at the same time" — `CLAUDE-EVT-02`: `TaskCreate` and `TaskUpdate` tool_use inputs are unchanged. The CLI's stored state is now correct under concurrency.
- "Fixed plugins going missing from the installed list when several `claude plugin` commands ran at the same time" — `CLAUDE-FILE-05`: `src/skills/scan.rs::scan_installed_plugins` sees fewer plugins missing. The layout it reads is unchanged.
- "Fixed the choice between two user or project agent files declaring the same name depending on the order the file search listed them" — `CLAUDE-FILE-05`: Mainframe's agents panel lists the files it finds and doesn't resolve name collisions. Only the CLI's pick becomes deterministic.
- "Fixed incomplete backups of `~/.claude.json` being kept, and displacing good ones, when the disk was full" — `CLAUDE-FILE-06`: concerns backup files only. `oauthAccount` and `projects[path].hasTrustDialogAccepted` in the main file are unchanged.
- "Improved `/resume`: sessions where you only opened a screen such as `/model` and left are no longer listed" — `CLAUDE-FILE-03`: a filter in the CLI's own picker. Mainframe's stat-only `*.jsonl` scan is unchanged and nothing says those transcripts stop being written.
- "Changed more `rm` commands aimed at the root, home, a top-level folder or the working folder to ask for approval; where nobody can answer, they're refused" — `CLAUDE-CTRL-01`: Mainframe answers through `--permission-prompt-tool stdio`, so these arrive as ordinary `can_use_tool` requests that a user can answer.

## Unannounced surface changes

From `binary-diff.mjs` (2.1.329 → 2.1.330, 29 items, bundle strings only). Two are announced (`CLAUDE_CODE_FULL_SIGN_IN_LINK`, `SELF_HOSTED_RUNNER_START_DIR`) and were classified with their entries. No removed item is cited by a checklist row, and none of the seven removed env vars appears anywhere in `packages/`.

- `offersBypassSwitchBack`, `keepsBypassHeld` (described schema keys, `initialize`) and `CLAUDE_CODE_RELAUNCH_BYPASS_SWITCH` (env var) — `CLAUDE-FLAG-01` / `CLAUDE-CTRL-03`, no action. `@internal` opt-ins that let the CLI start a bypassPermissions launch in `auto` and report it as `bypass_auto_switch` in the `initialize` response. Going back to bypass then needs `set_permission_mode` with `answers_bypass_switch_back`. They are honored only in the VS Code extension, and their absence fails closed. Mainframe declares neither key, so `--permission-mode bypassPermissions` still means bypass.
- `CLAUDE_CODE_HOST_ALLOW_RESETS_DENIAL_STREAK` (env var) — `CLAUDE-CTRL-01`, no action. A spawn-env opt-in for a `denial_limit_host_reset` request at three or more auto-mode blocks in a row. Mainframe doesn't set it, so behaviour at a denial streak is unchanged.
- `CLAUDE_CODE_DISABLE_REDIRECT_DENY_RECHECK` (env var) — `CLAUDE-CTRL-01`, no action. A kill switch that sits with the `rm`-prompt switches. Leaving it unset keeps the new recheck on, which can mean more `can_use_tool` requests, the same effect as the announced `rm` change.
- `CLAUDE_CODE_PROJECTS_FEATURE_FLAGS` (env var) — Not consumed (claude.ai Projects), no action. Mainframe never sets `CLAUDE_PROJECT_UUID`.
- Dropped from the binary diff: 21. They are `/access` (a `local-jsx` terminal screen for verification programs, gated on `tengu_gentle_sky`); the host, cowork and runner env vars `CLAUDE_CODE_COWORK_SHELL_CHECK`, `CLAUDE_CODE_HOST_READS_NO_BASH_EDIT_DIFF`, `CLAUDE_CODE_MODEL_NOBODY_CHOSE` (forwarded only in delegated and host session env lists), `CLAUDE_CODE_RUNNER_START_NOTES`, `CLAUDE_CODE_STARTER_MAY_HOLD_CONNECTOR_FILE`, `CLAUDE_CODE_STOP_ON_UNUSABLE_PROFILE` (provider profiles) and `CLAUDE_RUNNER_START_FOLDER`; `CLAUDE_MOD_MADE` (a worktree marker file); the schema keys `fullEscape` (REPL), `maxAgeMs` (settings-link cache), `pcm` (a MIME-table false positive), `releaseNote` (`ExitWorktree` output) and `unheard` (a CCR stream counter); and the 7 removed vars `API_FORCE_IDLE_TIMEOUT`, `AWS_BEARER_TOKEN_BEDROCK`, `BROWSER`, `BUF_BIGINT_DISABLE`, `ENABLE_CLAUDEAI_MCP_SERVERS` and two `OTEL_*`.
