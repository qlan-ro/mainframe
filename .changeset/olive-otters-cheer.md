The daemon now speaks the Agent Client Protocol (ACP v2) for chat. A new `/acp/{adapter-profile}` WebSocket endpoint serves the full facade: version-negotiated handshake, prompt acceptance and cancellation against live sessions, delta-only streaming with stable item IDs (a growing message is never re-sent whole), provider-retry markers instead of silently dropped `api_retry` events, resume-from-cursor replay that replaces the four separate reconnect mechanisms, and permission gates that stay consistent across the new and the existing chat surface. Edit/Write results stream as ACP `diff` tool-call content — structured changes plus git-patch text, with the hunks and before/after file text the desktop cards render riding the `_mainframe.dev` metadata namespace — and the subagent parent-attribution field now lives in that namespace as documented, instead of at the top level of `_meta`. Gate resolutions are pushed to every attached facade client the moment they happen (`_mainframe.dev/gate_resolved`), so a permission answered on one surface clears on the others without waiting for a resume. Truncated tool results carry their `truncated`/`fullBytes` marker through the facade too, restoring the "show full output" affordance, and chat teardown (archive, end, project removal) now clears the facade's per-chat gate and stream bookkeeping. Message content is block-indexed: a message holds an ordered list of `text` and `image` content blocks (per the pinned ACP schema), streamed as appending chunks with a full-replacement upsert for revisions — so inline images render as real images on the facade path instead of `[image]` placeholders, matching the legacy pipeline. The existing WebSocket dialect is unchanged and frozen; desktop and mobile keep using it until each cuts over.
