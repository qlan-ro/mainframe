The daemon now speaks the Agent Client Protocol (ACP v2) for chat. A new `/acp/{adapter-profile}` WebSocket endpoint serves the full facade: version-negotiated handshake, prompt acceptance and cancellation against live sessions, delta-only streaming with stable item IDs (a growing message is never re-sent whole), provider-retry markers instead of silently dropped `api_retry` events, resume-from-cursor replay that replaces the four separate reconnect mechanisms, and permission gates raised and answered entirely on this surface. Edit/Write results stream as ACP `diff` tool-call content — structured changes plus git-patch text, with the hunks and before/after file text the desktop cards render riding the `_mainframe.dev` metadata namespace — and the subagent parent-attribution field now lives in that namespace as documented, instead of at the top level of `_meta`. Gate resolutions are pushed to every attached facade client the moment they happen (`_mainframe.dev/gate_resolved`), so a permission answered on one surface clears on the others without waiting for a resume. Truncated tool results carry their `truncated`/`fullBytes` marker through the facade too, restoring the "show full output" affordance, and chat teardown (archive, end, project removal) now clears the facade's per-chat gate and stream bookkeeping. Message content is block-indexed: a message holds an ordered list of `text` and `image` content blocks (per the pinned ACP schema), streamed as appending chunks with a full-replacement upsert for revisions — so inline images render as real images on the facade path instead of `[image]` placeholders, matching the legacy pipeline. Streaming is now token-granularity end to end: the Claude adapter passes `--include-partial-messages` when the installed CLI supports it (version-gated, probed once per executable; older CLIs degrade to block-granularity instead of failing to spawn), accumulates the stream deltas, and feeds them through the shared display pipeline, so the facade emits true sub-message text/thought chunks. Assistant item ids now anchor on the provider message id so a streaming block keeps its identity from first delta through completion, resume, and history reload; a block aborted by a provider retry or interrupt is cleared everywhere instead of lingering. The legacy chat dialect is retired outright: the daemon no longer emits `display.message.*`, `message.added`/`.updated`, `permission.requested`/`.resolved`, `message.queued.*`, `messages.cleared`, `chat.compacting`/`chat.compactDone`, or `chat.contextUsage`, and no longer accepts `message.send`/`permission.respond` — the `/acp/{profile}` facade is the only chat wire protocol. What those frames carried beyond the core ACP grammar rides the `_mainframe.dev` extension surface instead: `queue_state` (the full queued-prompt snapshot on every change and as each resume replay's closing frame), `compaction` (started/done), `transcript_cleared` (re-resume on a server-side wipe), and the CLI's own context-occupancy percentage on `usage_update`'s metadata. The desktop chat controller consumes all of these; the side-band `/` WebSocket keeps only the non-chat domains (sessions list, launch, worktree offers, background tasks, workflows, automations, plugins, tunnels, file watches, quota, notifications), and its `subscribe` reply is now `worktree.offer.snapshot` followed by `subscribe:ack`. The sessions-list unread badge rides the `chat.updated` broadcast (`displayStatus: waiting`) that every gate raise emits. The mobile client spoke the removed dialect and is broken until its own facade migration lands in its own repository — an accepted consequence of retiring the dual-surface window.

The permission gate now renders the adapter's own ordered option list instead of a hardcoded allow/deny/always triad — button set, order, and labels come straight off the wire, styled by each option's `kind` (never its id or label), and an option kind the client doesn't recognize yet still renders and stays selectable rather than being dropped or guessed at. That tolerance now reaches the wire boundary too: the client schema admits unknown option kinds instead of dropping the whole permission request at parse time (a version-skewed daemon offering a novel kind degrades to a neutrally-styled button whose click answers as deny, never a wedged turn — spec decision 25), and the answer the client sends carries the `optionId` of the option actually clicked rather than one synthesized from the reply's behavior, so the plain half of the rich answer is truthful end to end. `reject_always` stays a recorded deviation: nothing offers it and the adapter control-response has no always-deny semantic, so it resolves as a one-shot deny (spec decision 26). The dead `_TaskProgress` tool card — unreachable since the encoder started flattening task-progress items into ordinary tool calls — is removed along with its registration, test, view-model types, and its only shared helper (`extractTaskId`/`taskResultText` in `@qlan-ro/mainframe-types`, which had no other consumer; the Rust daemon keeps its own independent mirror).

The diff engine keeps criterion 3's no-full-resend promise on meta-only changes: an item whose metadata changes while its content is untouched (turn end attaching `turnDurationMs`, a retry marker landing) now streams as a meta-only patch with `content` omitted, instead of re-sending the item's full accumulated content — and a cleared item meta wires as an explicit `null` patch rather than silently staying stale on the client.

A `session/request_permission` no longer drops silently when its daemon `_meta.controlRequest` payload is missing or unparseable — a version-skewed daemon build, or any non-Mainframe ACP agent that never sends the extension namespace at all. The adapter-supplied `options` are the presentation floor (spec decision 12): the client now synthesizes a minimal stand-in request and renders the generic options-only gate, falling back to the rich Plan/AskUserQuestion cards only when a real `controlRequest` carries the `input` those cards read (spec decision 27).

A round of review fixes closes ten blockers found against the facade: a prompt queued behind a running turn now appears once, at the tail, and stays there through the dequeue instead of reordering the transcript; a partial stream interrupted by a provider retry or an aborted turn no longer leaves a blank bubble above the real answer; clearing plan-mode context empties the transcript and it stays empty, instead of a stray update resurrecting it; Codex's Always-allow option now actually persists for the rest of the session instead of re-prompting next turn, and disappears from the gate entirely when the adapter offers no way to honor it; switching the active daemon drops every cached facade connection to the old one, so a prompt sent right after a switch cannot land on the wrong daemon; and a background chat you haven't opened stops streaming and reconnecting on your behalf — the facade client detaches when a thread goes inactive and reattaches, from its last item, when you switch back. Retrying a failed slash command now resends the command, not its literal text. A handful of ordering and lifetime defects are fixed alongside: a failed `initialize` handshake or a failed gate answer no longer leaks a socket or wedges the gate; a malformed permission request gets an error reply instead of hanging the turn; the connection watchdog keeps retrying after it first fires instead of going quiet; and a chat's queued-message cache hitting its cap now tells attached clients to resync instead of silently diverging.

Two more facade races close on the daemon side: reconnecting to a session you detached from mid-reconnect no longer resumes streaming to a surface that stopped listening, and a transcript wipe that lands while a reconnect is in flight no longer arrives ahead of the replay and blanks the transcript it was about to fill — it follows the replay instead, so the client reconnects onto the wiped state. A peer that has not completed the `initialize` handshake is now refused a subscription as well as the method it called.

A reconnect that keeps failing no longer loops: the daemon asks the client to resync once per failure streak, the client backs off between full replays (one second doubling to thirty, then it stops and logs the chat), and only one full replay runs at a time, with a transcript wipe never dropped behind a reconnect. A prompt, cancel, or resume whose daemon-side handling crashes now answers the request with a JSON-RPC error instead of hanging it, and Stop can no longer overtake the prompt it is meant to interrupt. A Codex question whose options carry no usable labels is offered as reject-only, so no client can send Codex a blank answer.
