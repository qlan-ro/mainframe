A PR that changes UI

  1. The source of this canvas is design/ in the repo. Every change goes through a PR; the hosted canvas is published from main by hand.
  2. One page per area. design/areas.json maps each area to its code paths, its boards and its surface brief.
  3. A PR that changes an area's UI code updates that area's boards or brief, captured from the running app, never drawn by hand. CI checks it; the design: none label skips it when nothing visible changes.
  4. Open design work lives on Proposals. The PR that builds it moves its frames to the area page and removes them from Proposals.

Status hues

primary — selected, or running and wants attention
success — connected, healthy or done. Never running.
warning — needs the user, or degraded
destructive — failed, or an irreversible action

Every artboard has a Theme tweak (light or dark). Reviews score each area page on its own, light and dark. Sessions were captured on the mock adapter, so provider marks and model names show its placeholders.
