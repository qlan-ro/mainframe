Window redesign: decisions log

Decisions for the composer, the session panel, the sidebar, the workspace surface and the window shell, as taken with Doru between 23 and 24 Nov 2026. This is the list implementation works from; newer entries override older ones.

•Visual reference: the Proposal-Redesign-* boards on this Proposals page, rendered from the final prototype.
•Clickable prototype: https://claude.ai/artifact/CvaibneH8Kp9fZ1Mw7VuXn. Open "Prototype controls" at the bottom left to jump to any state, switch theme or change the window width.
•Also binding: the transcript rework (T1) and the session-panel row sheets in the "Adopted from earlier proposals" section below the boards.

Status: final prototype, approved 24 Nov 2026. Being implemented: a row built in the app says "Implemented in #…". Items marked "proposed" change today's app behaviour and need a final yes when they are built.

Window shell

#DecisionNotes
S1The shell matches today's app.Full-width title bar, with the usage capsule beside the traffic lights, session tabs with close and +, and search plus the chat/code switch on the right. Nav rail as today. Sidebar header "Chats" with search and collapse, then the "New session" row, then the "All projects · N projects" scope row. Session header with the title on the left, side-chat and panel toggles on the right (no tasks chip, S4). The title bar is split into segments (W1). Reference: Proposal-Window-Baseline on the canvas. Implemented in #943.
S2The icon rail is its own column, with a hairline between it and the sidebar.Doru disliked the unseparated rail in the window proposal. Implemented in #943.
S3Scrollbars are overlay thumbs only: no track and no gutter, in every engine and with every macOS scroll bar setting. Native scrollbars are hidden (scrollbar-width: none, ::-webkit-scrollbar { display: none }). A 6 px thumb (ink at 26 %, 3 px radius, 2 px from the edge, minimum 24 px long) fades in while the area scrolls or is hovered, widens to 8 px (ink at 42 %) under the pointer, can be dragged, and fades out about a second later. The same behaviour everywhere in the app, not only the main window: sidebar, transcript, session panel, workspace, menus, popovers, dialogs, settings, automations, tasks, code views, Monaco (its own scrollbar set to the same slim overlay, no shadows) and the xterm terminal. In the app: hide native scrollbars globally and use Radix ScrollArea (components/ui/scroll-area.tsx, type="scroll" or "hover") for every scrolling region, with its thumb styled to these values.Updated 2026-11-24: the first version (a transparent track via scrollbar-color) still showed a grey track in WKWebView when macOS shows scroll bars always (the default with a mouse), and the 15 px gutter pushed the transcript text out of line with the composer (S5). Doru: "the scrollbar tracks... not what we discussed." First decided 2026-11-23: Doru didn't want the grey track the browser drew when scrollbars are always shown. Implemented in #941. One app-wide manager draws the thumb (packages/ui/src/lib/overlay-scrollbars) instead of Radix ScrollArea per region, so every container is covered; the app has no Monaco, and the terminal's bar sits in a 10 px lane. One exception: the HTML file preview keeps the engine's own scrollbars. It is a sandboxed frame with an opaque origin, so no thumb can be drawn for it, and hiding its bars would mean rewriting the user's document.
S4The session header has no "N tasks running" chip. It shows only the title, then the side-chat and panel toggles.Ongoing work shows in the composer's activity strip (K4) and in the panel's Activity section (R6). Doru: "remove that delegated tasks from chat header." Decided 2026-11-23. Implemented in #943.
S5The transcript scrolls across the whole main pane, so its scrollbar sits at the pane's right edge, not beside the reading column.The reading column and the composer stay centred at the column width, with text and composer edges aligned. This matches the Claude app, Antigravity and T3 Code. Decided 2026-11-23. Implemented in #943.
S6Failed work is muted rose, not red, across the app (--fail: #b04466 light, #e48aa3 dark): failed tool rows, the turn header's "N failed", failed Activity rows and counts, failed queue rows, error labels in tool bodies. Signal red (--crit) is kept for the two things that must be loud: the context ring at 95 % (C2) and the Stop square (C8), plus red output inside terminal text.Doru, 2026-11-24: "make this quieter, maybe some pink or sth, this is too loud, across the entire app". DESIGN.md calls the pair Muted Rose and Signal Red. Implemented in #941 for everything that was red; the failed-row glyphs and counts that are plain text today follow with their areas (T1, R rows).

Workspace surface

#DecisionNotes
W1The title bar is split into segments that line up with the columns below. Separators are small, 1 × 16 px in hair2, centred vertically. One sits exactly above the sidebar's right edge, between the usage capsule and the session tabs, and shows whenever the sidebar is open. The second sits exactly above the workspace panel's left edge and shows only while the workspace is open; its position is measured from what follows it, never a fixed offset. A third closes the workspace segment, after the workspace tabs, + and the Files toggle and before Search and the Chat / Workspace switch (Doru, 2026-11-24). So the title bar has three segments with the workspace open and two without, with the app-level controls set apart at the end.With the sidebar collapsed, the first separator follows the usage capsule, since there is no column edge to align to. Doru: "the titlebar should be split in 3 when workspace surface is visible." Decided 2026-11-24. Implemented in #943.
W2The workspace tabs move into the title bar's third segment. The panel has no tab strip of its own.Same 32 px tab shape as the session tabs, with a 12 px type glyph instead of the status dot: eye for a preview, globe for a URL, terminal for a shell or launched process, code for a file, diff for a diff. The selected tab is never truncated. Other tabs truncate down to 60 px (glyph plus a few letters, so a typical four-tab workspace fits without scrolling; Doru flagged the last tab sliced by the fade, 2026-11-24), and their close button appears on hover over the end of the title, so it takes no space. When the tabs overflow, the row scrolls with a fade at its right edge, and the selected tab scrolls into view. A fixed + after the tabs opens Open file…, New terminal ⌘J, URL… ⌘T, and the launch configurations. Decided 2026-11-24. Implemented in #943.
W3Search and the Chat / Workspace switch stay at the far right of the title bar, inside the workspace segment when it is open. The Files toggle (the docked file tree) sits at the right end of the workspace tabs.The switch's second button is labelled "Workspace" with ⌘⇧W, the app's binding (it was "Code"), and it opens and closes the panel. The prototype briefly used ⌘2, which belongs to session tab 2. Chat stays the floor surface, as today. Drawn as two plain title-bar toggles, not a segmented control: no outlined track; an "on" button gets the same soft fill and ink icon as the Files toggle, so Chat and Workspace both on reads as two lit toggles, not an odd double selection (Doru, 2026-11-24: "this looks odd, especially when both are on"). Implemented in #943.
W4The workspace opens as a panel that slides in from the right and pushes the chat column narrower. It does not cover it.0.32 s ease-out (cubic-bezier(.22,1,.36,1)), with no motion under prefers-reduced-motion. Default width is 50 % of the area right of the sidebar, never under 320 px, and the chat column keeps at least 360 px. Dragging the panel's left edge resizes it, and the title bar separator follows. Doru: "The workspace panel should show up as a sliding panel from the right." Decided 2026-11-24.
W5Workspace tabs follow the active session's scope, as today. Switching session swaps the tabs. A session with nothing open shows the empty state: Open file, New terminal, Open URL, and the launch configurations. Closing the last tab collapses the workspace (Doru, 2026-11-24); the empty state appears only when the workspace is opened with nothing in it.
W6Opening the workspace doesn't change the session panel directly. The narrower chat column parks it by the docking rule (R11). The panel toggle then floats it over the chat, and closing the workspace docks it again.Replaces the earlier proposal to hide the panel explicitly while the workspace is open. Decided 2026-11-24.
W7Not changed by this prototype, keeping today's behaviour: split workspace panes, the inline URL entry, the per-tab Stop for launched processes, and hiding chat for a workspace-only layout.Draw these when the proposal covers every component state (P1).
W8Agent tab. A sub-agent or delegated task opens as a workspace tab (bot or task icon). It shows the title, kind and status, a Stop button while the work is live, the brief, the steps as transcript rows, and the result. It opens from the row's "Open in workspace" action in the transcript and from the panel's Activity details.Decided 2026-11-24 (T1c). Reusing an open tab for the same agent.
W9The workspace surface retires split chats. Every secondary chat opens as a workspace tab beside the main chat, never as a split of the chat column: forked chats, side chats, delegated task chats and sub-agents (W8). The chat column always holds one conversation.Doru, 2026-11-24: "this will retire split chats, everything will open as a workspace surface tab. Forked chats, side chats etc."

Gates and shortcuts (carried over from today's app)

These exist in the app today. They were added to the prototype on 2026-11-24 so the critique scores the real product, not gaps in the prototype. Doru: "add to the prototype the parts from the app that the critique say are missing but we have them."

#DecisionNotes
G1Pending gates show in a slot pinned above the composer, one at a time, as ChatGateMount + GateCard do today. The slot is capped at 45 % of the height and scrolls inside. It sits above the activity strip.No refined proposal exists on the canvas, so the cards follow features/chat/gates/* and only take the prototype's tokens. The composer stays usable while a gate is pending.
G2Permission gate (PermissionGate): warning accent; a shield tile; eyebrow "Permission required"; the tool name in mono plus its command; a "Details" disclosure with the JSON input. Options come from the adapter: Allow once (primary), Always allow (outline, only when the CLI suggests a rule, and it names the rule, for example "Always allow cargo test *"), Reject (red tint).The option names match mainframe-acp/src/gates.rs. Answering resumes the turn and leaves a line in the transcript. The app's title is "Permission Required", repeating the eyebrow; that is kept as is. Proposed change from the app: the app makes Always allow the primary. The prototype makes the one-off grant the default and spells out what "always" saves. From the second critique, on 2026-11-24.
G3Plan gate (PlanGate): eyebrow "Plan", title "Ready to implement"; the plan body (capped at 300 px, scrolls); a mode segment (Interactive / Auto-edits / Auto / Unattended, Auto only where the adapter supports it); a "Clear context" checkbox; Approve & run (primary, full width), Keep planning (opens a feedback box with Cancel / Send feedback), and Reject.The mode segment preselects the composer's current mode, the "then …" in "Planning · then Auto-Edits", and uses the composer's spelling ("Auto-Edits"). Approving sets the permission mode to the chosen one and ends Planning. A waiting plan counts as "needs you" in the sidebar and tab.
G4Question gate (AskUserQuestionGate, restyled in Live mode on 2026-11-24, the "Spacing" polish variant): the question itself is the title (14 px semibold). Its context sits under it in grey: the header, "select all that apply" for multi-select, and the agent's name for a sub-agent. There's no small label above the title. Options and the Skip / Submit row align to the text column (50 px in), rows are compact (8 × 12 px padding), "(Recommended)" becomes a small blue "Recommended" tag, and the radio outline uses the meta grey so it passes 3:1. Proposed change from the app's card, which has the eyebrow "Question" over the header as the title, with the question text below. Option rows have a radio or checkbox and a description, plus "Other…" with a text field. Skip / Back / Next / Submit, with an "N of M" badge for several questions.
G5Requests surface on their own, oldest first. A sub-agent's or delegated task's permission request, question or plan shows in the same pinned slot as the session's own, without being opened by hand, as today's app does (ChatGateMount shows the queue front, selectPermissionFront). One shows at a time; answering it brings up the next. The eyebrow names who is asking and how many more wait ("Permission required · code-reviewer · 1 more waiting"). Answering turns the row back into a running item.Doru, 2026-11-24: "our code already surfaces the permission prompt, no need to open manually". Replaces the earlier proposal where "Open" on a needs-you row brought the gate up.
H1Keyboard shortcuts follow the app's registry (features/shortcuts/registry.ts): ⌘N new session, ⌘1…⌘9 session tabs, ⌃⇥ / ⌃⇧⇥ next and previous tab, ⌘B sidebar, ⌘⇧W workspace, ⌘⇧C chat, ⌘J new terminal, ⌘T new browser tab, ⌘K command palette, ⌘/ the shortcuts sheet. The redesign adds ⌘. (stop the turn and all sub-agents), ⌘; (project picker in a new session), ⌥↵ (queue or send now) and ⇧⇥ in the composer (cycle the permission mode, C12).The ⌘/ sheet is today's ShortcutsCheatSheet, grouped Sessions / Chat / Workspace / App, with the redesign's composer shortcuts listed under Chat. Implemented in #943 (the sheet and the registry rows; ⌘., ⌘;, ⌥↵ and ⇧⇥ join it with their handlers).

Transcript

#DecisionNotes
T1The transcript follows the transcript proposal (Proposal-Transcript-Window).Folded turns "✓ Worked for 2m 14s · edited 3 files, ran 2 commands · 1 failed ›", which expand and collapse. Prose with inline code, times under messages, neutral user bubbles, and dividers for "Context compacted" and "Switched to … · context handed off".
T1aEvery tool the app renders gets a row in the same grammar (glyph, verb, target, receipt, chevron), checked against features/chat/tools/register-cards.ts, the Codex adapter's item mapping and the fallback card on 2026-11-24. The proposal had no rows for 11 tools, now drawn on Proposal-Transcript-Rows (two new columns) and in the prototype's "Transcript: every tool card" preset: LS ("Listed"), ExitPlanMode ("Updated plan", "Plan approved"), AskUserQuestion ("Asked" with the chosen answer), Skill ("Used skill /name", which absorbs the separate "Using skill" pill), Workflow / RunWorkflow ("Started workflow", opens the run), mcp__mainframe__delegate_task ("Codex task" / "Claude task"; its steps are rows, its gate is answered above the composer, G5), CollabAgent ("Codex agent", like a sub-agent), PushNotification ("Notified"), the schedule tools (ScheduleWakeup, CronCreate, CronDelete, CronList, Monitor), EnterWorktree / ExitWorktree, and image results (thumbnails in the body; Codex image generation).Superseded in part by T1g: skills, plans, questions, schedules, monitors, worktree operations and notifications are markers, not rows. MCP calls stay rows (proposal decision 2). Codex dynamic tools (namespace__tool) and any unregistered tool use the "Called" row with arguments and result. Hidden tools stay hidden (TodoWrite, the Task* progress tools, EnterPlanMode, ToolSearch, Codex todo_list). Doru: "make sure we're not missing any tool the app handles."
T1bTranscript fixes from the 2026-11-24 critique (23/36). (1) One row system: realistic turns use the same rows as the reference thread, and every row opens. (2) Times: there is no time line under each message. A centred marker shows the time at the start of the conversation ("Today, 11:18 PM") and again wherever 30+ minutes pass or the day changes. Each message's own time sits in its footer, next to Copy, Fork and More (user messages: Copy and More). The footer appears on hover or keyboard focus and keeps its height so nothing moves; the full date is in its tooltip. (3) Turn status: the turn's glyph follows how it ended (done, stopped, error). A failed step is shown as "N failed" in muted rose (--fail), or as "1 failed, retried" in grey when a later step in the same turn runs the same tool on the same target and succeeds. That is the only "fixed" signal the app can derive (tool name, input, isError); nothing links attempts. Clicking the count opens the turn on the failed step. An unresolved failed row opens by itself. (4) One markdown dialect: every code block has the language header and Copy, and every table has the frame. (6) One work row per turn: an agent's response to one user message has a single "Worked for …" row. Text the agent writes between steps sits inside that work, as a plain line between rows, and only its final text is the answer. (5) Components: diff text is ink on the tint (colour only in the +/− column), the terminal follows the theme, the "where" text ("on GitHub") is visible, 24 px targets, h3 13 px semibold, a grey quote bar, task boxes that don't look disabled, web results in the UI face, and distinct worktree glyphs.Proposed: message actions and the time model (from MT-11, extended). The canvas transcript boards are not updated yet; Doru reviews the prototype first.
T1cSub-agents and delegated tasks are nearly the same thing on screen. The card and its behaviour are alike, with only a slight difference so they can be told apart (a delegated task uses the same robot icon as a sub-agent, filled; and it names its own chat and provider). Both use Stop, never Cancel, in the transcript, the composer strip, the panel and the workspace. Both open in the workspace's Agent tab (W8).Doru, 2026-11-24, answering the delegated-tasks critique (24/40): "there should be only a slight difference between subagents and delegated chats, enough to recognize… Cancel/Stop terminology should be the same. I should be able to open subagents too." The other delegated-task fixes are on hold until Activity is polished.
T1eChild work holds the turn open. While a turn's sub-agents, delegated tasks or workflows are still going (running, queued or waiting on you), its work row shows a small spinner instead of the ✓, does not fold by default, and its header carries the live count, needs-you first: "7 agents · 1 needs you · 1 running · 1 queued". Once all have finished the turn folds like any other step and the header still names them ("2 agents", "1 workflow"); the summary text no longer repeats them. Clicking the count opens the turn and lands on the first one still going, else the first one. Monitors and background commands don't hold the turn open; they live in Activity. Agents are never pulled out of the turn: Activity (R13) and the Agent tab (W8) are the way back to them.Doru, 2026-11-24 ("ok" to the proposal after comparing Codex and Claude Code). Codex's app keeps sub-agent activity as its own row inside "Worked for …" and skips the default fold while a background agent is active; Claude Code's CLI has no turn fold. Resolves delegated-tasks critique issue 1.
T1fA delegated task's result merges into its card, as a sub-agent's does: the card gains the Result block and its final status in place. The separate task-result message the parent receives (<mainframe-task-result>, today's AgentMessageCard, several results batched into one) is not drawn in the transcript, and no marker replaces it; the parent agent's next turn simply follows. Anything else sent to the task's chat (a follow-up round) shows in the card too, because the card shows the task's own transcript.Doru, 2026-11-24: "should we merge the response… in the same tool card? that's how subagents work". Chose merging with no marker.
T1gEvent tools are markers: centred pills on the spine, outside the folded work. Skill ("Used skill /name"), ExitPlanMode ("Updated plan", and "Plan approved · implementing with Auto-Edits" once approved), the schedule tools (ScheduleWakeup, CronCreate, CronDelete, CronList), Monitor (running: spinner and time at the end of the pill), EnterWorktree / ExitWorktree ("Entered worktree", "Left worktree · kept", "Removed worktree") and PushNotification ("Notified"). A pill is 26 px, fully rounded, hairline, icon then label; it sits under the turn's one "Worked" row, in the order the events happened, and stays visible when the work folds. A pill with content opens a card under it: a plan is its markdown (as PlanCard and PlanBubble render it today), a schedule list its jobs, a monitor its output, a notification its message, a skill its SKILL.md. Questions are asked through the gate above the composer (G4); the answered question stays outside "Worked" as a small card: question, the chosen answer chips, the note. Activity rows for monitors and schedules jump to their pill (R13).Doru, 2026-11-24: "i still want this to be a marker with a pill… updated plan and plan approved also need a marker and their content is markdown… the same markers for schedules, monitors, worktree operations… notifications the same. Questions are like a permission card themselves, above the composer, answers should stay outside Worked". Today's app already draws schedules, monitors and worktrees as centred markers (marker-pill.tsx, SchedulePillCard, WorktreeStatusPillCard); this brings skills, plans and notifications into the same family and gives them the pill.
T1dLinks in replies share one style and open in one place. Blue text with an underline. Every URL, web or local server, opens where Settings › General › "Open links in" says: the workspace browser (a URL tab, the default) or the system's default browser. So a web link and http://localhost:5173 look and behave the same; a raw URL is in mono and keeps its prefix. Exception, remote daemon: a local-server URL (localhost, 127.0.0.1, 0.0.0.0) points at the daemon's machine, so Mainframe opens it through the daemon's tunnel (the proxied address for that port), still in the place the setting names. The link text stays as written; its tooltip says it opens through the tunnel, and the context menu carries the tunnel state and Stop tunnel. On a local daemon the word "tunnel" never appears, as today's UrlChip does. A file link opens in the workspace editor; it shows the path in mono with no glyph (the <> code glyph read as the Workspace switch and was removed, Doru 2026-11-24). Footnote markers jump to their note. The localhost chip (status dot, trailing button) is retired; the tunnel state and Stop move to the link's context menu. Slash instructions stay chips, because they are actions, not links.Doru, 2026-11-24: "why do we have 3 ways of showing URLs?… we should be consistent with what we open… we should always open the default engine, we should set it in settings." New setting to build: Settings › General › Open links in (Workspace / Browser).
