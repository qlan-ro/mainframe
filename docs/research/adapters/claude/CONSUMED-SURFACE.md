# Claude CLI consumed-surface checklist

Source of truth: `packages/core-rs/crates/mainframe-adapter-claude/`. Per the
crate's `src/lib.rs` doc comment: **unknown inbound event types are logged at
debug on every occurrence and skipped — never a hard error.** There is also **no typed
enum for stream-json events**: `src/events.rs` compares `serde_json::Value`
string fields throughout (`event.get("type").and_then(Value::as_str)`, and
likewise for every `subtype`). Silent degradation on unknown or renamed
upstream input is exactly why a changelog watcher exists — a rename here
produces no compile error and no runtime error, only a dropped event.

See `docs/research/adapters/README.md` for the row schema, ID grammar, and citation
rules.

## Not consumed — adoption candidates

- `--include-partial-messages` (would enable `stream_event` deltas, see CLAUDE-EVT-06), `--session-id`, `--settings`, `--mcp-config`, `--agents`, `--fork-session` — flags Mainframe never passes.
- `hook_callback` and `mcp_message` `control_request` subtypes — dropped by the same catch-all as every other unhandled subtype (CLAUDE-CTRL-01).
- `~/.claude/projects/*/sessions-index.json` and `~/.claude/todos/` are **not** read — Mainframe scans `*.jsonl` directly and takes todos from the TodoWrite tool stream (CLAUDE-EVT-02), so upstream changes to either file are noise, not risk.
- `src/pr_detection.rs` reads Bash **tool inputs**, not a CLI protocol surface — an upstream CLI change cannot break it, so it is intentionally excluded from this table.
