# Rust crate audit log

The nightly code-audit run picks one crate under `packages/core-rs/crates`,
fixes what it finds in one PR, and records the crate here. Pick a crate that
is not listed yet, or the one audited longest ago. Follow-ups are findings
the run left open because they cross a crate or wire boundary.

| Date | Crate | PR | Follow-ups |
|---|---|---|---|
| 2026-10-21 | `mainframe-git` | #861 | `update_all` reports a failed pull of the current branch as `up-to-date` (`UpdateAllResult` has no failure variant; needs a types + UI change). The git diff route builds `{base}..HEAD` from a query value without an option guard (`mainframe-server/src/routes/git.rs`). Merge results report the auto-merged file count as `commits`. |
| 2026-11-07 | `mainframe-runtime` | #886 | `~/.mainframe` is created `0755`, so other local users can list it and read `mainframe.db` and the logs. A `config.json` with one invalid field (for example `port: 70000`) still fails as a whole: the daemon mints a new auth secret and devices must re-pair, though the old file now survives as `config.json.invalid.<timestamp>`. `tunnel_manager.rs` `next_line_stdout`/`next_line_stderr` drop the reader on non-UTF-8 output, the bug fixed here in `spawn_line_pump`. `write_workspace_trust` replaces a symlinked `~/.claude.json` with a regular file. `save_config` runs sync file I/O inside async tunnel handlers. `finish_pumps` and `PumpTasks` still abort a pump after the grace period, so a job left holding a `ManagedProcess` pipe dies on SIGPIPE; `run_captured` now keeps draining instead. |
| 2026-11-09 | `mainframe-db` | #887 | `DevicesRepository::update_last_seen` has no caller, so `mainframe status` shows every paired device as last seen "never" (wire it at the server's device-auth check). Removing a project deletes its chats but keeps their `delegated_tasks` rows (the table has no foreign keys), so `list_owed` can return a task whose parent chat is gone. `get_pending_fork` fails on a corrupt `pending_fork` value while every other JSON column logs and falls back to a default; settle the policy with the fork flow in `mainframe-chat`. Enums persist three ways (`SqlEnum` serde, `as_db_str`/`from_db_str` for segments, `as_str`/`parse` for orchestration); converge them in `mainframe-types`. |
| 2026-11-18 | `mainframe-background-tasks` | #919 | Tests still swap the lsof, tree-kill and `ps` seams by locking a `Mutex` inside the production `ProcessDeps`; an injected `ProcessProbe` trait passed at construction would remove the mutable seams but touches every kill, liveness and reconcile test. `SessionLike::stop_background_task` returns an `ok: bool` plus optional error mirroring the adapter's `StopBackgroundTaskResult`; converge both on a `Result` in `mainframe-adapter-api`. Spool paths cross the crate as `String` (`BackgroundTask::output_path` is a wire field), so non-UTF-8 paths are lossy end to end. Three `tracker_tests_part_*.rs` files are stitched together with `include!`; move them to the `foo_tests.rs` layout from R12. |
| 2026-11-20 | `mainframe-lsp` | #925 | Server-to-client requests (`workspace/configuration`, `client/registerCapability`) sent while no editor is attached are dropped, so the server waits for a reply that never comes; answering them needs a policy per method. A second editor that connects before the first one's `initialize` result is cached forwards a second `initialize`, which servers reject. A reconnecting editor re-sends `didOpen` for documents the server still has open. `mainframe_types::lsp::LspServerConfig` and its TypeScript twin no longer have a consumer; delete both. `routes/lsp_routes.rs` still hand-writes Zod error strings. |
| 2026-11-21 | `mainframe-github` | #928 | `IssuePatch::state_reason` is a free `String` that only ever carries `"completed"`; an enum needs the todos plugin call sites changed too. `RateLimited::wait` stays an `Option` although the client now always sets it, because the plugin's fakes and capability guard construct it with `None`. The device-flow route answers 502 for every non-config failure, including an OAuth rejection such as `device_flow_disabled`, which is a GitHub App setting rather than a gateway fault. |
| 2026-11-22 | `mainframe-services` | #936 | `POST /api/chats/{id}/attach-worktree` stores any client path and branch without checking they are a linked worktree of the project (`mainframe-server/src/routes/worktree.rs`); `remove_worktree` now refuses to delete such a directory or its branch, but the route should reject them up front. `Project::parent_project_id` has no reader in the UI or mobile app, and projects the old backfill linked to each other stay cyclic in existing databases. A mobile device with an open socket still receives pushes: `PushService` never had device presence wired (the unused `connected` flag is removed here). `wrap_mainframe_command` interpolates the command name into an XML attribute unescaped. `WorktreeError::Git(String)` flattens `GitExecError`, so `config_manager` answers a git timeout with 400. `quota/manager_tests_part_*.rs` and `attachment/attachment_store_tests_part_*.rs` are still stitched together with `include!`. |
| 2026-11-23 | `mainframe-launch` | #937 | `LaunchManager` and `TunnelManager` are still the same supervisor written twice (two spawn gates, two TERM→KILL ladders, two exit watchers); converging them onto one `mainframe-runtime` supervisor is the baseline's process R-item. `LaunchConfiguration::port` stays `i64` in `mainframe-types` and its TypeScript twin although only 1–65535 parses now; narrowing it to `u16` is a types change. `ResolveCloudflaredDeps::platform` selects the platform with a string (`"win32"`) while `SweepDeps::platform` uses an enum. The launch start route still holds the HTTP request open for the whole port wait (up to 60s); answering once the process is spawned would need the UI to rely on `launch.status` events alone. |
| 2026-11-25 | `mainframe-orchestration` | #956 | `ChatManager::send_message` answers `Ok` without delivering when the chat's worktree is missing, so a held result is recorded as delivered and a delegated task prompt as running (`mainframe-chat/src/chat_manager/send_entry.rs`). The HTTP routes that stop or cancel (`chats/{id}/interrupt`, `delegated-tasks/{taskId}/cancel`) and the `external_mcp` mutations still run inside the request future, so a client that disconnects can leave a Stop cascade or a launch half done. `launch.rs` archives a chat whose launch fails after `enable_worktree` but leaves its new worktree and branch behind. The ceiling picks its privilege table with `adapter_id == "codex"` (`policy.rs`); the rank and meaning belong on `AdapterCapabilities`. Pending permissions, message reads and `project_exists` still turn a DB error into "nothing there" at the port. `external_mcp/wait.rs` keeps its own copy of the wait-slot counter that is a `Semaphore` here. `AdapterView` carries `installed` and `available` with the same value. Nothing escapes a message body that contains a marker's closing tag. |

A new defaulted method that it does not override runs the default no-op instead of reaching the chat, and no test catches the gap. `AdapterSession` (42 methods), `SessionSink` (30) and `Adapter` (29) are wide ports. `SkillsProvider::list_error` passes the 500 body text through a trait method; it belongs on the error. `AdapterRegistry::refresh_all` probes adapters one at a time, so a slow CLI delays the others behind the 2s cap in `list`.
