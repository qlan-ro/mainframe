## ⭐ Golden rule: chat/thread/thread-list components — assistant-ui first, **stop-and-ask on mismatch**

**Layering (user decision, 2026-08-06):** **assistant-ui owns state and behavior; shadcn owns pixels.** aui
primitives render INTO shadcn chat markup; aui's styled registry components contribute nothing visual. When
both libraries "have" a component it is almost always behavior-vs-look — compose them rather than choosing.

For **any chat / thread / thread-list / message / tool-card / permission / composer component**, follow this process — never skip it:

1. **Research** what assistant-ui provides for it. Check the **latest published release** — not just our pinned/installed version — because the API moves fast and a newer component may justify a bump; **and** check the *installed source* for what we actually have today (docs drift from both). Look in the package exports AND the shadcn **registry** (`@assistant-ui/react-ui` / `npx shadcn add` components like `model-selector`), which ship components into our repo rather than as imports. For each candidate, confirm whether its runtime wiring (e.g. `ModelContext`, `useAssistantInstructions`) is **inert under our `useExternalStoreRuntime`** — if so it's a presentational shell only and we keep our own daemon write path.
2. **Compare** it to our warm-chrome prototype design (the relevant artboard).
3. **If it matches** → use the assistant-ui component, **restyled** to the design. Do not rebuild what it provides.
4. **If it does NOT match** → **STOP. Build neither version yet.** Present a concise **side-by-side summary — our design vs the native assistant-ui component** (what each offers, where they diverge, the cost of each direction) and **ask for a decision.**

Never silently (a) rebuild what assistant-ui already provides, nor (b) force a native component that doesn't fit the design — a mismatch is a **human decision**. *(Subagents can't prompt the user: on a mismatch, STOP, build nothing, and return the design-vs-native summary to the orchestrator, who asks.)*

## Runtime & data
- **`useExternalStoreRuntime`** fed by a **per-chat controller** (the `react-opencode` shape: `AcpChatController` + pure reducer + projection; transcript/run/gates via `AcpSessionPlane` on the shared `/acp/{profile}` facade client, side-band config/tasks/offers via `ChatWsSubscription` + `chat-event-router`). **Not** AssistantTransport.
- **No app-side message cache.** The daemon is the single source of truth; the controller holds only the per-chat projection (item accumulator + converted messages). Drift is handled by the facade's **heartbeat gap → `session/resume` replay** from the last settled item (unknown/compacted cursor → full replay), not a client cache, a daemon `seq`, or a REST refetch — the four legacy re-seed paths are retired.
- **Optimistic-send reconcile = count-aware + server-authoritative** (judo-A). One matcher (`chat-reconcile.ts`) clears optimistic pendings against confirmed server user-messages via a multiset: each server copy clears at most one pending, oldest-first. Every facade `transcript.updated` feeds it the full converted user-message list. **No time window, no empty-text wildcard, no over-clearing** of legitimate duplicate sends.
- Sessions list via **`useRemoteThreadListRuntime`** + `chats-remote-adapter` (step 11, built). Global runtime mounted ONCE in App.tsx (App is the real root: DaemonPortProvider → AssistantRuntimeProvider). `useChatRuntimeHook` resolves per-thread context via `useAuiState((s) => s.threadListItem)` and keys the controller by the stable `item.id`; WS sub gated to the active thread (isActive = mainThreadId === item.id && item.remoteId != null). WS list side-effects (reload/unread/cross-project-filter-clear/archived-active-fallback) run via `useSessionListRouter()` under the provider.

## Architecture
- **Feature-first** under `features/`; `layout/` + `surfaces/` only *compose* features into the two typed surfaces (Chat/Workspace). No feature imports `layout/`.
- **Surface intent, not reach-through:** a feature that needs to open a file/diff/surface emits an intent; never `someStore.getState().openX()`.
- **`lib/tauri/` is the only Tauri-aware module** — all `window.mainframe.*` equivalents live there (Rust commands/events).
- **Pure logic** (convert-acp-item, diff math, file-types) goes in a shared bundleable location, **not** the `mainframe-core` *sidecar process*.

## Surface model (Chat · Workspace)

**TWO surfaces since the 2026-08-05 merge.** `SurfaceId` is `'chat' | 'workspace'`; the Files and Run surfaces are one `WorkspaceSurface` holding files, diffs, viewers, terminals, consoles, previews and URL tabs in a single pane model. Files/Run no longer exist as ids, components, stores, or drop targets.

- **One tab/pane model:** `store/run-pane.ts` (1–2 panes along an axis, per-tab `scopeKey`) plus `store/run-pane-file-tabs.ts` for the file-tab semantics — one preview slot per pane per launch scope, open-again focuses, permanent appends, `promoteFileTab` on double-click or first edit. The parallel Files tab store is deleted; there is no `useTabsStore`, and nothing bridges tabs between surfaces. `addRunTab` keeps its signature (consumer contract). Read a file tab out of the model with `activeFileTab(run)`, never by reaching into panes at a call site.
- **Every tab is scope-stamped** at creation from the active session (`useActiveBasesStore.scopeKey`), and the surface renders only tabs matching the active scope (`filterRunByScope`). "My open files" is per project/worktree, not per chat. The exception is `chat` and `agent` tabs (`isConversationTab`): they belong to the session and show in every scope.
- **Chat tabs never lose an unsent message.** Closing one, hiding the workspace or switching session only takes it off screen: `DraftKeeper` carries the composer's text and files through `draft-stash` to whichever composer shows that chat next (the tab again, or the chat column via `use-chat-thread-runtime`). Exactly one composer owns a chat at a time (`mounted-conversations` → `composing`). Deleting a side chat is a separate, confirmed Discard.
- **Hiding is not closing.** `toggleSurface('workspace')` preserves the panes and kills nothing: the surface holds the user's open files, and the terminal cache detaches without disposing. Kill-before-remove (`terminal-cleanup.ts`) and tunnel release (`url-tunnel-cleanup.ts`) belong to the real close paths — `closeRunTab`, `closePane`, `releaseRunScope`.
- **Dynamic floor — NOT a hardcoded chat floor (decision corrected 2026-06-21).** The non-dismissable "floor" is **whichever surface is the *last lit one*** (`isFloor = lit && litCount === 1`), not `id === 'chat'`. **Chat is hideable**: every session tab's context menu carries **Hide Chat** (`session-tab-ctx-hide-chat`) and the title bar's Chat and Workspace toggles hide either surface; each is disabled at the floor. If a toggle would empty the row, fall back to showing chat (`store/layout.ts` restore-`['chat']`).
- **Persistence:** `mf:session-layout` is at **v3**. Its migration folds persisted `files`/`run` ids into `workspace` (dedupe, carry flex weights), brings a workspace parked in the old bottom strip back beside the chat, and passes persisted tabs through — they already carry the `RunTab` shape. `mf:session-tabs` is at **v4** (a v3 split pair becomes a chat tab in each member's workspace, `migrate-split.ts`). Only the safe kinds are written (`SAFE_RUN_TAB_KINDS`); a tab with no `mode` reads as permanent.
- **Placement is SETTLED (2026-08-08, todos #308/#309; Files-panel docking reversed 2026-08-15; chat header retired 2026-10-04).** Multi-session is chrome-style **session tabs in the title bar** (`features/session-tabs/` — the active session is the focused tab, ONE chat surface); a second chat column is REJECTED (W9) — a session opens beside the conversation as a workspace tab. `layout-placement.ts` has two surfaces in one row, chat left; the workspace slides in and pushes the chat (W4: half the row by default, 320 px minimum, the chat keeps 360). Open in Workspace and Hide chat live on every session tab's context menu (`session-tab-ctx-open-workspace|hide-chat`). The Files tree lives INSIDE the workspace surface as a **persistent DOCKED sidebar** on its right edge (`WorkspaceFilesPanel`, built on the shared `Sidebar` primitive, `side="right"`/`collapsible="offcanvas"`; opened from the title bar's Files toggle; open state persists per project/worktree scope in `store/workspace-files-panel`, closes only via its own toggle — no light-dismiss). The panel resizes/pushes the content pane rather than overlaying it. Surfaces never exchange tabs. Plan: `docs/plans/2026-08-08-session-tabs-and-workspace-files.md`.

## Component layer & theme
- **shadcn/ui**, not raw Radix. Build the `components/ui/` primitives once; features compose them.
- Theme via the tokens in `src/styles/globals.css`. **Read the `mainframe-design-system` skill before writing markup or class names** — it carries the scales, the recipes, and the traps.
- **Token trap:** use only `mf-*` names that `@theme inline` actually maps; a typo renders as nothing, with no error. The same holds for stock names Tailwind never generated — `text-xl` is a live example. As of 2026-08-08 the bridge is RETIRED: `styles/domain-tokens.css` (né `legacy-bridge.css`) holds only first-class domain palettes and app chrome; every generic `mf-*` colour and the whole v1 type scale are gone (use `text-xs/sm/base/lg`). The `/opacity` modifier *does* work here (Tailwind v4 compiles it to `color-mix`) — the old blanket prohibition was a v3 carryover from `packages/app-electron`. It only misleads on `accent`/`border`/`input`, which are already alpha.

## Conventions
- **No file > 300 lines**, no function > 50. Decompose god-files on port (don't carry them).
- **Every interactive element needs a stable `data-testid`** (`<surface>-<element>`); `ui/` primitives stay passthrough.
- **`convert-acp-item` invariants are load-bearing:** stable item ids are the aui message keys (identical live, in resume replay, and in history — spec decision 3), subagent nesting comes from parent-attribution `_meta` (the WS14c `task_group` dual re-encode is retired with the dialect), ≥1-content-part + error fallbacks stay. Identity too: an untouched container returns the same `ThreadMessageLike` (and parts) on every conversion — assistant-ui memoizes on object identity, and the per-chunk render cost of the whole transcript depends on it.
- **Pin the whole `@assistant-ui/*` set together, exact** — currently `react@0.15.38` / `store@0.3.25` / `core@0.3.38` / `tap@0.9.27` / `react-markdown@0.14.26`, every one an exact version (was the `0.14.27`/`0.2.21` line). They're independently versioned and sub-1.0 — never let `^` ranges drift them apart. `react-markdown` must move in lockstep (`0.14.26` peers `react ^0.15.0`). *Historical: the ban on `0.14.19`/`0.14.20` (React-Compiler subscription bug, fixed in `.21`) is superseded by the 0.15 line.*
- **Drop, don't port,** obsolete code: the `zone/` layout, layout/ui stores, the dual tool dispatcher, regex go-to-definition.

## Known gaps / phantom deps
There's no separate deferred-backlog doc — the gaps that bite *inside this package* day-to-day live here:
- **Restored-permission "stream closed" gap** — replying to a *restored* permission whose CLI process died (daemon restart between question and answer) fails with "stream closed"; it **self-recovers on reload**, and plain reconnect with the CLI alive works. **PUSHED OUT to Post-V1 (2026-06-23)** — not a V1 blocker; see the tracker's *Pushed out — Post-V1* section.

## Daemon contract
Chat rides the **ACP facade** — `/acp/{adapter-profile}` WebSocket, pinned protocol v2 plus the `_mainframe.dev` extension namespace (`lib/daemon/acp-client.ts`; spec: `docs/specs/2026-08-28-todo-350-wire-protocol-payload-grammar.md`). It is the ONLY chat wire protocol: the legacy chat dialect (`display.message.*`, `message.send`, `permission.*`, `message.queued.*`, …) is deleted daemon-side (spec decision 24). The side-band `/` WS keeps the non-chat domains (sessions list, config `chat.updated`, launch, background tasks, worktree offers, workflows, notifications). The mobile-co-ownership additive-only rule is retired with the dialect — mobile is broken until its own facade migration lands in its own repo (accepted, decision 24); contract changes are governed by the spec's decision log, not by mobile compatibility.
