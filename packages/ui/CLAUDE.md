# `@qlan-ro/mainframe-ui`

The new **Tauri 2 + React** desktop UI — a _parallel_ rebuild of `packages/app-electron` (Electron), not a modification of it. Treat `desktop/` as **reference only** (behavior + the visual target); never edit it from here.

> **New here?** Start with the root `CLAUDE.md` (monorepo code rules), then this file. The migration-era doc set this pointer used to name (`MIGRATION-INDEX.md`, `docs/design-reference/`, the runtime ADR, `MIGRATION-TRACKER.md`) never made it into the tree — this file is the current map.

## assistant-ui boundary

This replaces the old "assistant-ui first, stop and ask" rule. Do not look for an assistant-ui answer to transcript code.

- **assistant-ui owns** the composer field's behaviour (drafts, IME, paste, key handling), attachments, quoting and selection, the action bar, and the session list. It stays the runtime bridge through `useExternalStoreRuntime`.
- **Mainframe owns the transcript:** the data path, turns, rows, the list, scrolling, paging, sub-agents, gates and the queue. The transcript scrolls inside `ThreadPrimitive.Viewport`, but Mainframe owns its scroll behaviour; assistant-ui's auto-scroll stays off. Do not adopt `onLoadEarlier`, `createThreadRowsSelector` or `ThreadPrimitive.Row`: the last two don't fold turns, and they end a turn at every user message, queued ones included (#948).
- **shadcn owns presentation** for rows (Trace), gates (Questionnaire, Item), code (Code Block; markdown code blocks use it already), scroll (a hand-written owner, not Message Scroller: see below) and the composer's card (Input Group), tiles (Attachment) and buttons. "shadcn" means its core components and its AI Elements at ui.shadcn.com, never the deprecated `vercel/ai-elements`. Adopt shadcn's component unless it lacks something we need, and say what that is. For scroll, the proof ([transcript list rig](../../docs/research/2026-11-26-transcript-list-rig.md)) picked a hand-written owner (`v1`: plain rows, browser anchoring, about 110 lines). Message Scroller 0.3.1 follows a frame late (it defers to rAF) and releases follow on a downward wheel. Patching both in a vendored copy fixes those, but it still loses a reader parked at offset 0 when a page lands (42 px), ends 200 px short of the wheel when a page lands mid-wheel in WebKit, and its upward release did not always hold in Chromium. `preserveScrollOnPrepend={false}` is no way out: the library then reads a prepend as a new turn and scrolls to it.
- **Two transcript lists, one setting.** Settings › Chat › "Plain transcript list (preview)" (`plainTranscript` in `store/ui-prefs.ts`, off by default for one release) switches the list. Off is the list above: react-virtuoso in `ThreadPrimitive.Viewport`. On is `OwnedChatThreadViewport.tsx`: a plain scroller (not assistant-ui's viewport, so its `messagesPrepended` correction cannot fight the owner), `PlainMessages` (every loaded row, tail-first mount through `use-tail-first-rows.ts`, no virtualizer, no `content-visibility`) and `use-scroll-owner.ts` as the one writer of the scroll position, with browser scroll anchoring on and the composer below the scroller. `MessagePrimitive.Root` renders without the viewport store (tested in `ChatThread-plain-transcript.test.tsx`). Under the owner the row anchor and the prepend anchor do nothing (`controller.owned`). The old path stays intact until the setting is removed. Both transcripts hide the scrollbar thumb (`data-scrollbar="none"`). On the plain list the loaded window is bounded and jumps load around their target: `AcpHistory.trim()` cuts the live window to its newest page when the reader returns to the bottom (`use-trim-at-tail.ts`), only when the daemon advertises `historyTrim` (it raises the connection's history floor first: the daemon serves a page only `before` its floor), and `AcpHistory.load(target)` opens a snapshot window with `history_around` (`acp-history-around.ts`) instead of paging everything between. The live accumulator keeps taking every update while that window shows, and `state.messages` stays the live transcript for every reader (export, Activity, gates, sub-agent tabs: `useLiveMessages`); the window is `state.windowMessages`, projected only into the main transcript's runtime; the window re-fetches on resync, compaction, a cleared transcript and turn end, and a send or the scroll-to-bottom button returns to the tail (`returnToTail`). The old in-page find (`find/legacy-find.ts`, `search-messages.ts`) runs on the old list only; delete it with that list.
- **assistant-ui 0.15.38 specifics:**
  - No `ThreadPrimitive.ViewportFooter`: its height counts as "at bottom". The footer above the composer is a plain div.
  - All of assistant-ui's viewport scrolling is off: `autoScroll`, `scrollToBottomOnThreadSwitch`, `scrollToBottomOnRunStart`, `scrollToBottomOnInitialize`, and composer focus on switch (`unstable_focusOnThreadSwitched`).
  - The viewport's prepend scroll correction (`messagesPrepended`) has no switch. Expect it when rows are prepended.
  - Mainframe's bottom pin (`features/chat/thread/use-thread-bottom-pin.ts`) is the only code that follows streaming output. Do not add another follower or turn assistant-ui's back on.
- Bump assistant-ui only for a fix we need, and pin the set exactly (see Conventions). The `INTERNAL` import (the composer's input-plugin registry) breaks first on a bump.

Research: [shadcn agent components](../../docs/research/2026-11-26-shadcn-agent-components.md), [composer study](../../docs/research/2026-11-26-composer-shadcn-study.md). How each chat area is built today: [chat area notes](docs/chat-area-notes.md).

## Runtime & data

- **`useExternalStoreRuntime`** fed by a **per-chat controller** (the `react-opencode` shape: `AcpChatController` + pure reducer + projection; transcript/run/gates via `AcpSessionPlane` on the shared `/acp/{profile}` facade client, side-band config/tasks/offers via `ChatWsSubscription` + `chat-event-router`). **Not** AssistantTransport.
- **No app-side message cache.** The daemon is the single source of truth; the controller holds only the per-chat projection (item accumulator + converted messages). Drift is handled by the facade's **heartbeat gap → `session/resume` replay** from the last settled item (unknown/compacted cursor → full replay), not a client cache, a daemon `seq`, or a REST refetch — the four legacy re-seed paths are retired.
- **Optimistic-send reconcile = count-aware + server-authoritative** (judo-A). One matcher (`chat-reconcile.ts`) clears optimistic pendings against confirmed server user-messages via a multiset: each server copy clears at most one pending, oldest-first. Every facade `transcript.updated` feeds it the full converted user-message list. **No time window, no empty-text wildcard, no over-clearing** of legitimate duplicate sends.
- Sessions list via **`useRemoteThreadListRuntime`** + `chats-remote-adapter` (step 11, built). Global runtime mounted ONCE in App.tsx (App is the real root: DaemonPortProvider → AssistantRuntimeProvider). `useChatRuntimeHook` resolves per-thread context via `useAuiState((s) => s.threadListItem)` and keys the controller by the stable `item.id`; WS sub gated to the active thread (isActive = mainThreadId === item.id && item.remoteId != null). WS list side-effects (reload/unread/cross-project-filter-clear/archived-active-fallback) run via `useSessionListRouter()` under the provider.

## Architecture

- **Feature-first** under `features/`; `layout/` + `surfaces/` only _compose_ features into the two typed surfaces (Chat/Workspace). No feature imports `layout/`.
- **Surface intent, not reach-through:** a feature that needs to open a file/diff/surface emits an intent; never `someStore.getState().openX()`.
- **`lib/tauri/` is the only Tauri-aware module** — all `window.mainframe.*` equivalents live there (Rust commands/events).
- **Pure logic** (convert-acp-item, diff math, file-types) goes in a shared bundleable location, **not** the `mainframe-core` _sidecar process_.

## Surface model (Chat · Workspace)

**TWO surfaces since the 2026-08-05 merge.** `SurfaceId` is `'chat' | 'workspace'`; the Files and Run surfaces are one `WorkspaceSurface` holding files, diffs, viewers, terminals, consoles, previews and URL tabs in a single pane model. Files/Run no longer exist as ids, components, stores, or drop targets.

- **One tab/pane model:** `store/run-pane.ts` (1–2 panes along an axis, per-tab `scopeKey`) plus `store/run-pane-file-tabs.ts` for the file-tab semantics — one preview slot per pane per launch scope, open-again focuses, permanent appends, `promoteFileTab` on double-click or first edit. The parallel Files tab store is deleted; there is no `useTabsStore`, and nothing bridges tabs between surfaces. `addRunTab` keeps its signature (consumer contract). Read a file tab out of the model with `activeFileTab(run)`, never by reaching into panes at a call site.
- **Every tab is scope-stamped** at creation from the active session (`useActiveBasesStore.scopeKey`), and the surface renders only tabs matching the active scope (`filterRunByScope`). "My open files" is per project/worktree, not per chat. The exception is `chat` and `agent` tabs (`isConversationTab`): they belong to the session and show in every scope.
- **Chat tabs never lose an unsent message.** Closing one, hiding the workspace or switching session only takes it off screen: `DraftKeeper` carries the composer's text and files through `draft-stash` to whichever composer shows that chat next (the tab again, or the chat column via `use-chat-thread-runtime`). Exactly one composer owns a chat at a time (`mounted-conversations` → `composing`). Deleting a side chat is a separate, confirmed Discard.
- **Hiding is not closing.** `toggleSurface('workspace')` preserves the panes and kills nothing: the surface holds the user's open files, and the terminal cache detaches without disposing. Kill-before-remove (`terminal-cleanup.ts`) and tunnel release (`url-tunnel-cleanup.ts`) belong to the real close paths — `closeRunTab`, `closePane`, `releaseRunScope`.
- **Dynamic floor — NOT a hardcoded chat floor (decision corrected 2026-06-21).** The non-dismissable "floor" is **whichever surface is the _last lit one_** (`isFloor = lit && litCount === 1`), not `id === 'chat'`. **Chat is hideable**: every session tab's context menu carries **Hide Chat** (`session-tab-ctx-hide-chat`) and the title bar's Chat and Workspace toggles hide either surface; each is disabled at the floor. If a toggle would empty the row, fall back to showing chat (`store/layout.ts` restore-`['chat']`).
- **Persistence:** `mf:session-layout` is at **v3**. Its migration folds persisted `files`/`run` ids into `workspace` (dedupe, carry flex weights), brings a workspace parked in the old bottom strip back beside the chat, and passes persisted tabs through — they already carry the `RunTab` shape. `mf:session-tabs` is at **v4** (a v3 split pair becomes a chat tab in each member's workspace, `migrate-split.ts`). Only the safe kinds are written (`SAFE_RUN_TAB_KINDS`); a tab with no `mode` reads as permanent.
- **Placement is SETTLED (2026-08-08, todos #308/#309; Files-panel docking reversed 2026-08-15; chat header retired 2026-10-04).** Multi-session is chrome-style **session tabs in the title bar** (`features/session-tabs/` — the active session is the focused tab, ONE chat surface); a second chat column is REJECTED (W9) — a session opens beside the conversation as a workspace tab. `layout-placement.ts` has two surfaces in one row, chat left; the workspace slides in and pushes the chat (W4: half the row by default, 320 px minimum, the chat keeps 360). Open in Workspace and Hide chat live on every session tab's context menu (`session-tab-ctx-open-workspace|hide-chat`). The Files tree lives INSIDE the workspace surface as a **persistent DOCKED sidebar** on its right edge (`WorkspaceFilesPanel`, built on the shared `Sidebar` primitive, `side="right"`/`collapsible="offcanvas"`; opened from the title bar's Files toggle; open state persists per project/worktree scope in `store/workspace-files-panel`, closes only via its own toggle — no light-dismiss). The panel resizes/pushes the content pane rather than overlaying it. Surfaces never exchange tabs. Plan: `docs/plans/2026-08-08-session-tabs-and-workspace-files.md`.

## Component layer & theme

- **shadcn/ui**, not raw Radix. Build the `components/ui/` primitives once; features compose them.
- Theme via the tokens in `src/styles/globals.css`. **Read the `mainframe-design-system` skill before writing markup or class names** — it carries the scales, the recipes, and the traps.
- **Token trap:** use only `mf-*` names that `@theme inline` actually maps; a typo renders as nothing, with no error. The same holds for stock names Tailwind never generated — `text-xl` is a live example. As of 2026-08-08 the bridge is RETIRED: `styles/domain-tokens.css` (né `legacy-bridge.css`) holds only first-class domain palettes and app chrome; every generic `mf-*` colour and the whole v1 type scale are gone (use `text-xs/sm/base/lg`). The `/opacity` modifier _does_ work here (Tailwind v4 compiles it to `color-mix`) — the old blanket prohibition was a v3 carryover from `packages/app-electron`. It only misleads on `accent`/`border`/`input`, which are already alpha.

## Conventions

- **No file > 300 lines**, no function > 50. Decompose god-files on port (don't carry them).
- **Every interactive element needs a stable `data-testid`** (`<surface>-<element>`); `ui/` primitives stay passthrough.
- **`convert-acp-item` invariants are load-bearing:** stable item ids are the aui message keys (identical live, in resume replay, and in history — spec decision 3), subagent nesting comes from parent-attribution `_meta` (the WS14c `task_group` dual re-encode is retired with the dialect), ≥1-content-part + error fallbacks stay. Identity too: an untouched container returns the same `ThreadMessageLike` (and parts) on every conversion — assistant-ui memoizes on object identity, and the per-chunk render cost of the whole transcript depends on it.
- **Pin the whole `@assistant-ui/*` set together, exact** — currently `react@0.15.38` / `store@0.3.25` / `core@0.3.38` / `tap@0.9.27`, every one an exact version (was the `0.14.27`/`0.2.21` line). They're independently versioned and sub-1.0 — never let `^` ranges drift them apart. `@assistant-ui/react-markdown` is gone: transcript markdown renders through Streamdown (exact pin), see the chat area notes. _Historical: the ban on `0.14.19`/`0.14.20` (React-Compiler subscription bug, fixed in `.21`) is superseded by the 0.15 line._
- **Drop, don't port,** obsolete code: the `zone/` layout, layout/ui stores, the dual tool dispatcher, regex go-to-definition.

## Known gaps / phantom deps

There's no separate deferred-backlog doc — the gaps that bite _inside this package_ day-to-day live here:

- **Restored-permission "stream closed" gap** — replying to a _restored_ permission whose CLI process died (daemon restart between question and answer) fails with "stream closed"; it **self-recovers on reload**, and plain reconnect with the CLI alive works. **PUSHED OUT to Post-V1 (2026-06-23)** — not a V1 blocker; see the tracker's _Pushed out — Post-V1_ section.

## Daemon contract

Chat rides the **ACP facade** — `/acp/{adapter-profile}` WebSocket, pinned protocol v2 plus the `_mainframe.dev` extension namespace (`lib/daemon/acp-client.ts`; spec: `docs/specs/2026-08-28-todo-350-wire-protocol-payload-grammar.md`). It is the ONLY chat wire protocol: the legacy chat dialect (`display.message.*`, `message.send`, `permission.*`, `message.queued.*`, …) is deleted daemon-side (spec decision 24). The side-band `/` WS keeps the non-chat domains (sessions list, config `chat.updated`, launch, background tasks, worktree offers, workflows, notifications). The mobile-co-ownership additive-only rule is retired with the dialect — mobile is broken until its own facade migration lands in its own repo (accepted, decision 24); contract changes are governed by the spec's decision log, not by mobile compatibility.
